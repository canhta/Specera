# OpenGrok

A Java servlet application (Oracle, ex-Sun) that runs universal-ctags plus ~50 hand-written JFlex lexers over a source tree, writes one Lucene document and one static HTML "cross-reference" page per file, and serves search + browsing from a Tomcat war.

## 1. Verdict

`INFERENCE` (from §2, §4, §6): **a source of design lessons, not a component.** The one thing OpenGrok does better than anything else in this group is **document-granular incremental reindex with typed invalidation**: its Lucene uid is `path + last-modified-millisecond` (`analysis/AnalyzerGuru.java:596`, `Util.path2uid`), and each analyzer carries its own version stamp so bumping the Java lexer reindexes only Java files (`index/IndexDatabase.java:2309-2317`). That is strictly better than [zoekt](zoekt.md)'s default whole-shard rebuild, and it is the idea worth stealing. What kills it as a component is threefold: `FACT` the license is **CDDL-1.0 only** (`LICENSE.txt:1-4`), a file-level weak copyleft that is GPL-incompatible and forces source disclosure for any modified OpenGrok file Specera ships; `FACT` its "cross-reference" is not a reference graph at all — every identifier is hyperlinked to a *full-text search URL* (`?refs=<symbol>`, `analysis/JFlexXrefUtils.java:264-275`), so there is no resolved edge to consume programmatically; and `FACT` the project is at maintenance rate — 7,790 commits since the 2005-era import, but only 57 in the last six months (150 in twelve), with the last commit a CI script fix (`b9be6fdcaa5`, 2026-06-25).

## 2. Core architecture and unique mechanism

`FACT` **Two artifacts per source file, not one.** `index/IndexDatabase.java:1179-1200` builds a Lucene `Document` *and* writes an HTML cross-reference file to the data root through a transient-then-rename completer (`PendingFileRenaming`). `isGenerateHtml()` defaults to `true` (`configuration/Configuration.java:579`). The web app serves the pre-rendered HTML; it does not re-highlight at request time. `INFERENCE`: disk cost is the Lucene index *plus* a full HTML mirror of the corpus — a materially larger multiplier than zoekt's published 3.5×, and OpenGrok publishes no figure at all.

`FACT` **Lucene 9.12.3** (`pom.xml:63`). Document schema is fixed in `search/QueryBuilder.java:52-77`. Public fields: `full` (all tokens), `defs` (ctags definitions), `refs` (all symbol occurrences), `path`, `hist` (VCS log text), `type`, `scopes`, `numl`, `loc`, `lastrev`. Internal fields: `u` (the uid — path + timestamp), `d` (directory), `t` (genre), `fullpath`, `dirpath` (SHA-1 normalised), `project`, `date`, and `objuid`/`objser`/`objver` for the serialised `Definitions` blob. **`defs` and `refs` are separate token streams over the same file — that is the entire "cross-reference" data model.** There is no edge table, no symbol id, no resolution.

`FACT` **What "cross-reference" actually means.** `analysis/JFlexXrefUtils.java:217-296`, `writeSymbol()`, has exactly three outcomes per identifier:
1. the symbol is a language keyword → emit `<b>`, no link (`:225-231`);
2. the symbol is *defined in this file exactly once* → emit an in-page anchor `href="#symbol"` (`:276-277`, `writeSameFileLinkSymbol():306-321`) — the only true resolved link in the system, and it is intra-file only;
3. everything else → emit `<a href="…?defs=<symbol>">` or, at a definition site, `<a href="…?refs=<symbol>">` (`:264-275`, `:283-293`).
`INFERENCE`: OpenGrok's navigation is **string-matched search dressed as navigation**. Two unrelated classes with a `run()` method collapse into one "reference" set. Nothing in the index distinguishes a call from a mention in a comment string beyond the lexer's token class.

`FACT` **Symbols come from a ctags subprocess, one long-lived process per indexer thread.** `analysis/Ctags.java:172-292` builds the command line: `--fields=-af+iKnS` (`:199`), plus kind widening for locals (`--kinds-c=+l`, `--kinds-java=+l`, `--kinds-sql=+l`, `--kinds-C++=+l`, `--kinds-Fortran=+L`, `:184-194`). Output is parsed by `CtagsReader` into a `Definitions` object which is Java-serialised into the `objser` field. `ctagsTimeout` defaults to **10 seconds** per file (`configuration/Configuration.java:573`). There is **no sandbox** around ctags — contrast zoekt, which requires a seccomp build (`doc/ctags.md` there).

`FACT` **Tokenisation and highlighting are 97 hand-written JFlex grammars** (`find . -name '*.lex' | wc -l` → 97) across ~50 language packages under `opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/` (ada, c, clojure, cobol, csharp, eiffel, erlang, fortran, golang, haskell, hcl, java, javascript, kotlin, lisp, lua, ocaml, pascal, perl, php, powershell, python, r, ruby, rust, scala, sh, sql, swift, tcl, terraform, typescript, vb, verilog, yaml, …). `AnalyzerGuru` dispatches by magic bytes, extension, and prefix. Non-source genres are handled too — archives, `JarAnalyzer`, ELF executables, documents.

`FACT` **Incremental reindex — the decisive code path.** `IndexDatabase.update()` (`:578-733`) opens the existing `DirectoryReader`, gets a sorted `TermsEnum` over the `u` field (`:620-651`), then calls `getIndexDownArgs()` (`:835-859`) which picks one of two collectors:

- **History-based** (`indexDownUsingHistory():906-933`): asks a `FileCollector` for the exact set of paths changed since the last indexed revision, sorts them, and for each one calls `processFileHistoryBased()` (`:1666-1727`). Cost is O(changed files). This is the good path.
- **Filesystem walk** (`indexDown():1616-1643`): recurses the whole source tree, `stat`s every file, and merge-joins the sorted walk against the sorted uid terms in `processFile()` (`:1759-1830`). If the term equals `path+mtime` exactly, the file is skipped; if the term sorts lower, the old document is deleted; otherwise the file is queued for `addFile()`. Cost is O(all files) in stat calls but still only reindexes changed documents.

`FACT` **The good path is gated behind seven conditions and is off by default.** `isReadyForHistoryBasedReindex()` (`:458-540`) returns false unless: projects are enabled; `project != null`; `project.isHistoryEnabled()`; `env.isHistoryCache()`; `project.isHistoryBasedReindex()`; the index is non-empty; a `FileCollector` exists; the project has ≥1 repository; **and every repository is a `RepositoryWithHistoryTraversal`** (`:547-570`). Only `GitRepository` and `MercurialRepository` extend that class (`history/GitRepository.java:99`, `history/MercurialRepository.java:57`) — Subversion, Perforce, CVS, Bazaar, RCS, SCCS all fall back. And `setHistoryEnabled(false)` is the **default** (`configuration/Configuration.java:585`), while `setHistoryBasedReindex(true)` (`:583`) is meaningless without it. `INFERENCE`: out of the box OpenGrok does a full filesystem walk on every reindex; you must explicitly enable history to get change-set-driven collection, and then only for Git/Mercurial projects.

`FACT` **Typed invalidation via version stamps.** `checkSettings()` (`:2239-2338`) is called for files whose uid matched, to decide whether a *format* change forces reindex anyway. It compares the stored tab size, the stored global `AnalyzerGuru` version (`analysis/AnalyzerGuru.java:357-365`, currently the date-stamped literal `20260504_00`), the stored file-type name, and — the interesting part — the **per-analyzer version** `AnalyzerGuru.getAnalyzerVersionNo(fileTypeName)` against `settings.getAnalyzerVersion(fileTypeName)` (`:2309-2317`). A bump to one language's lexer therefore reindexes only that language's files.

`FACT` **Parallelism model**: serial collection stage then `indexParallel()` (`:1838-1900`) over a fixed executor, with one `Ctags` instance per worker. Lucene RAM buffer defaults to 16MB (`configuration/Configuration.java:225,608`) with the in-repo comment `//below can cause an outofmemory error, since it is defaulting to NO LIMIT`.

## 3. Strongest capabilities

- `FACT` **Document-granular incremental update with a merge-join against the index.** `processFile():1759-1830` walks the sorted uid `TermsEnum` in lockstep with the sorted directory walk. Adding, modifying, deleting, and renaming are all handled in one pass with no full rebuild. This is the single mechanism zoekt does not have.
- `FACT` **Per-analyzer version stamps as invalidation keys** (`index/IndexDatabase.java:2309-2317`, `analysis/AnalyzerGuru.java:357-380`). Changing one lexer invalidates one file type, not the corpus.
- `FACT` **VCS history is a first-class indexed field.** `analysis/AnalyzerGuru.java:651-667` pulls `History` from `HistoryGuru`, indexes the commit-message text into the `hist` field, stores the last revision in `lastrev`, and populates an annotation (blame) cache. `hist:` is a queryable dimension alongside `full:`, `defs:`, `refs:`, `path:`. No other tool in this group indexes commit messages next to code in the same document.
- `FACT` **Breadth of format coverage.** 97 JFlex grammars plus archive/binary analyzers means `.jar`, `.zip`, ELF, and document formats are all searchable, not just plain source.
- `FACT` **A real REST API**, documented in `openapi.yaml`: `/search`, `/file/defs`, `/file/content`, `/file/genre`, `/annotation`, `/history`, `/suggest`, `/projects/*`, `/system/indextime`, `/metrics/prometheus`. Bearer-token auth on protected endpoints (`openapi.yaml:6-16`).
- `FACT` **Pluggable authorization with an LDAP implementation shipped.** `authorization/AuthorizationFramework.java:153,186` evaluates a plugin stack per `Project` and per `Group`; `plugins/src/main/java/opengrok/auth/plugin/` contains `LdapUserPlugin`, `LdapAttrPlugin`, `LdapFilterPlugin`, `UserWhiteListPlugin`, plus SSO header decoders.
- `FACT` **293 `*Test.java` files**, 114 of them under `analysis/` — the lexers, the ctags parser (`CtagsParserTest`, `CtagsTest`), and the xref writers (`JFlexXrefTest`, `XrefTestBase`) are genuinely tested per language. Sonar coverage badge is wired into the README.
- `FACT` **A separate query suggester module** (`suggester/`, 31 source files) that tracks per-project term popularity (`suggester/.../popular/`) and feeds `/suggest`.

## 4. Critical weaknesses

- `FACT` **The cross-reference is not a graph.** `analysis/JFlexXrefUtils.java:276-293` — a symbol not defined in the current file, or defined more than once in it, gets a link to a *search query*, with the comment "we can't generate a direct link to the definition". There is no cross-file resolution, no call graph, no type information, no cross-repository edge. Dynamic wiring (DI containers, reflection, message queues, HTTP between services) is invisible, and so is static cross-file linkage.
- `FACT` **The index has no repository boundary concept beyond `project`.** `Project`/`Group` are grouping and *authorization* units (`authorization/AuthorizationFramework.java:153,186`), not graph scopes. Cross-repository questions degrade to "does this string appear in another project's documents".
- `FACT` **Freshness is timestamp-based and therefore lossy.** The uid is `path + file.lastModified()` (`analysis/AnalyzerGuru.java:593-597`). `isStrictlyNewerThanDocument():865-897` compares mtime to the stored `date` field. `INFERENCE`: any workflow that rewrites mtimes without changing content (fresh clone, `cp -r`, container rebuild, some CI checkout modes) forces a full reindex; conversely, content changed with a preserved mtime is silently missed. Content hashing would not have this failure mode.
- `FACT` **A minor version bump requires a full clean reindex.** `README.md:39` — "minor - full clean reindex of your repositories is needed (e. g. index format has changed)"; "major - major backwards incompatible update, will require full reindex as well as configuration changes". `docker/README.md` advises pinning to `x.y` tags specifically "to avoid reindexing from scratch". `INFERENCE`: the fine-grained incremental machinery is undone by the upgrade cadence.
- `FACT` **The vendor's own container documentation disclaims large workloads.** `docker/README.md`: "The indexer and the web container are **not** tuned for large workloads. If you happen to have one of the following: large source data (e.g. AOSP or the like) … then it is advisable to run OpenGrok standalone or construct your own Docker image."
- `FACT` **Heap-bound search was still a live bug in 2026.** Commit `097b76306f4` (2026-06-15), "fix(search-api): bound Lucene collection to prevent OOM": "The REST search API collected all matching Lucene documents into memory before paginating, causing OutOfMemoryError on large indexes. For a broad full-text query like 'magical' across all projects, the unbounded re-collection path in SearchEngine loaded every matching ScoreDoc into heap." `INFERENCE`: after 20 years, the scaling envelope is still being discovered by users hitting OOM.
- `FACT` **Silent analyzer failures.** `index/IndexDatabase.java:1206-1212` — any exception from an analyzer is caught and logged at `INFO` as "Skipped file … because the analyzer didn't understand it", with the stack trace only at `FINE`. Combined with the 10-second ctags timeout (`configuration/Configuration.java:573`), files can silently end up in the index with no `defs`.
- `FACT` **ctags is not sandboxed.** `analysis/Ctags.java` spawns the binary directly with no seccomp/namespace isolation, over attacker-supplied source. This is the standard C-parser-on-untrusted-input attack surface, unmitigated.
- `FACT` **No relevance or performance benchmark exists in the repo.** No JMH harness, no `bench`/`benchmark` directory, no golden-ranking fixtures. Correctness of lexing is tested per language; ranking quality and index-size/throughput characteristics are entirely unmeasured, and no figures are published in-repo.
- `FACT` **Six additional bundled licenses** beyond CDDL: `LICENSE-adaic.org.txt`, `LICENSE-eclipse.txt`, `LICENSE-ecma.txt`, `LICENSE-mandoc.txt`, `LICENSE-ruby.txt`, `LICENSE-scala.txt`, plus `NOTICE.txt` covering Apache-licensed dependencies. `INFERENCE`: any vendoring requires a per-file license audit, not a single-license decision.
- `FACT` **Maintenance rate.** 7,790 commits total; 150 in the last twelve months, 57 in the last six. The HEAD commit `b9be6fdcaa5` (2026-06-25) changes `dev/openapi.sh` — a CI helper. The surrounding commits are Dependabot bumps and shell-style fixes. `INFERENCE`: mature and still patched, but not evolving.

## 6. Security, deployment, and license

`FACT` **License: CDDL-1.0 only** — `LICENSE.txt:1-4`: "Unless otherwise noted, all files in this distribution are released under the Common Development and Distribution License (CDDL), Version 1.0 **only**." Every source file carries a `CDDL HEADER` block (e.g. `search/QueryBuilder.java:1-18`). Copyright "2006, 2025 Oracle and/or its affiliates" (`README.md:1`).

The reuse consequences, read from the license text:
- `FACT` **§3.1 (`LICENSE.txt:156-167`)**: any Covered Software distributed in Executable form must also be made available in **Source Code form under CDDL**. This is per-file copyleft: it attaches to OpenGrok files Specera modifies, not to Specera's own code.
- `FACT` **§3.6 Larger Works (`LICENSE.txt:219-225`)**: Specera *may* combine OpenGrok with proprietary code and ship the combination as one product, provided CDDL obligations are met for the OpenGrok files. So linking is legally permitted — but every patched OpenGrok file must be published.
- `FACT` **§3.4 (`LICENSE.txt:186-201`)**: Specera may not impose additional terms on the CDDL source form.
- `FACT` **§3.3 (`LICENSE.txt:177-185`)**: each modification must carry a notice identifying Specera as contributor; existing notices may not be removed.
- `FACT` **Jurisdiction is fixed** (`LICENSE.txt:381-387`): California law, Northern District of California / Santa Clara County venue.
- `INFERENCE`: **CDDL-1.0 is GPL-incompatible** — it is a file-level copyleft with its own source-disclosure and venue terms that GPL §6-style "no further restrictions" clauses forbid. `UNVERIFIED` as a legal conclusion for Specera specifically: this is the widely held reading (it is why OpenJDK was relicensed and why CDDL Java EE code could not link to GPL code), but it is not stated in `LICENSE.txt` itself. Verifiable only by counsel. The practical effect for Specera is concrete regardless: **CDDL code cannot be mixed into any GPL/AGPL-licensed component Specera might also use, and every touched file must be published.**
- `FACT` **Six additional license files** ship alongside: `LICENSE-adaic.org.txt`, `LICENSE-eclipse.txt`, `LICENSE-ecma.txt`, `LICENSE-mandoc.txt`, `LICENSE-ruby.txt`, `LICENSE-scala.txt` — grammar/spec material borrowed into the lexers. `NOTICE.txt` additionally lists Apache-licensed dependencies (Lucene, snowball stemmers, ICU4J, SmartChineseAnalyzer). `INFERENCE`: a vendoring decision requires auditing which of the 97 `.lex` files are encumbered by which of these six, not one blanket CDDL judgement.

`FACT` **Deployment: a Java servlet war on Tomcat, plus a separate indexer JVM.** `Dockerfile:44` bases the runtime on `tomcat:10.1.55-jdk21`; `opengrok-web/src/main/webapp/WEB-INF/web.xml` is Jakarta EE 6.0. Configuration is a single XML file read at startup — `CONFIGURATION` context-param, default `/var/opengrok/etc/configuration.xml`. The indexer is a separate CLI process (`index/Indexer.java`) driven by Python wrappers in `tools/src/main/python/opengrok_tools/` (`indexer.py`, `mirror.py`, `sync.py`, `reindex_project.py`, `projadm.py`). The official image reindexes on a timer, default every 10 minutes (`docker/README.md`). Self-host only; there is no SaaS.

`FACT` **Auth model: none by default, plugin stack when configured.** `web.xml` installs `AuthorizationFilter` over `/*`; `authorization/AuthorizationFramework.java:153-194` evaluates a stack of plugins per `Project` and per `Group`. `setPluginStack(new AuthorizationStack(AuthControlFlag.REQUIRED, "default stack"))` with an empty stack is the default (`configuration/Configuration.java:601`). `INFERENCE`: **authorization granularity is the project, not the file or the branch** — there is no per-path ACL and no query-rewriting mechanism equivalent to zoekt's branch-mask approach. A repository with mixed-sensitivity contents cannot be partially exposed.

`FACT` **REST auth is a shared bearer token** (`openapi.yaml:6-10`), with an `allowInsecureTokens` option to permit it over plain HTTP. `/system/ping`, `/system/indextime`, `/suggest/config`, `/metrics` are unauthenticated by design (`openapi.yaml:15-16`).

`FACT` **Egress**: the indexer shells out to VCS clients (git, hg, svn, p4, cvs, bzr, RCS, SCCS — `docker/README.md`) to mirror and to read history; the LDAP plugins call an LDAP server; `plugins/.../util/WebHooks.java` can POST to configured webhook URLs. No model provider is contacted anywhere.

`FACT` **Prompt-injection surface: none.** There is no LLM, no embedding, and no natural-language path anywhere in the tree. `INFERENCE`: as with zoekt, any injection risk in a Specera deployment would be created by Specera piping OpenGrok output into a model, not inherited.

`FACT` **Untrusted-input surface is real and unmitigated**: universal-ctags is spawned as a subprocess over customer source with a 10s timeout and no sandbox (`analysis/Ctags.java:172-292`, `configuration/Configuration.java:573`), and archive/executable analyzers (`analysis/archive/`, `analysis/executables/`) parse jar/zip/ELF structures in the indexer JVM.

## 7. Ideas to adopt or avoid

### Adopt

- **Per-analyzer version stamps stored in the index, checked at reindex time** (`index/IndexDatabase.java:2309-2317`; `analysis/AnalyzerGuru.java:357-380`, version literal `20260504_00`). Specera should stamp every derived artifact with the version of the extractor that produced it, per language and per artifact type. Then shipping a fix to the Python extractor reindexes Python files only, instead of triggering a corpus-wide rebuild. This is the highest-value idea in the repo and it composes with zoekt's `IndexState` enum: version stamps say *what* is stale, `IndexState` says *why*.
- **The sorted-merge-join between a directory walk and the index's sorted key iterator** (`processFile():1759-1830`). Specera needs exactly this shape to reconcile "what is on disk" against "what is indexed" in one linear pass, detecting adds, modifies, and deletes together, without materialising two full sets in memory.
- **A single set of changed paths derived from VCS history, feeding the indexer** (`indexDownUsingHistory():906-933` + `FileCollector`). Specera should make this the *only* path — compute the changed-path set from the commit range and drive every downstream extractor from it — rather than OpenGrok's arrangement where it is one of two paths behind seven preconditions.
- **Indexing commit-message text into the same document as the file** (`analysis/AnalyzerGuru.java:651-667`, the `hist` field). "Find the code whose commit messages mention this incident" is a maintenance query Specera will need, and putting `hist` alongside `full`/`defs`/`refs` in one document makes it a single query rather than a join.
- **Two-phase write with a pending-completer** (`index/PendingFileCompleter.java`, `PendingFileRenaming`/`PendingFileDeletion`/`PendingSymlinkage`): derived files are written to `<path>.pending` and atomically renamed only after the index commit succeeds. Specera should use this for every derived artifact so a crashed indexer never leaves half-written outputs that look valid.
- **A dedicated `IndexCheck` verification command** (`index/IndexCheck.java`, with `IndexCheckMode` and `checkVersion()`) that can be run independently to assert the index matches the source tree and the format version. Specera should ship an equivalent `specera verify` from day one rather than adding it after the first silent-corruption incident.

### Avoid

- **`path + mtime` as the freshness key** (`analysis/AnalyzerGuru.java:593-597`). Specera should key on content hash + commit SHA. Timestamps produce both false rebuilds (fresh clone, container image rebuild) and false skips (content changed, mtime preserved).
- **Generating a static HTML mirror of the corpus as an indexing side effect** (`index/IndexDatabase.java:1184-1200`). It doubles storage, makes the "index" two coupled stores that can diverge, and freezes presentation into the index format. Render at query time.
- **Encoding navigation as search-query URLs** (`analysis/JFlexXrefUtils.java:264-293`). Once "go to definition" is `?defs=name`, nothing downstream can consume a reference as data — no graph query, no impact analysis, no LLM context assembly by edge traversal. If Specera builds a symbol graph, the edge must be a first-class stored record with a target id, and the UI link is derived from it, not the other way round.
- **Project-level authorization only** (`authorization/AuthorizationFramework.java:153-194`). Specera's ACL granularity must be at least path-level and must be expressible inside the query (zoekt's rewriting model), not evaluated as a post-filter per project.
- **Requiring a full clean reindex on minor version bumps** (`README.md:39`). This is the failure mode that makes per-file incrementality irrelevant in practice. Specera's index format must be versioned per artifact type with a migration path, which is precisely what the per-analyzer version stamps above enable if applied to the format as well as the extractors.
- **Catching every analyzer exception and logging it at `INFO`** (`index/IndexDatabase.java:1206-1212`). Extraction failures must be counted, surfaced as a metric, and attached to the affected document as a quality flag, so a query can tell "no results" from "this file was never successfully parsed".
- **Spawning a C parser over customer source with no sandbox** (`analysis/Ctags.java:172-292`).

## 8. Build, borrow, buy, integrate, or reject

**REJECT as a component; BORROW the incremental-reindex design.** The license is the primary blocker: CDDL-1.0 only (`LICENSE.txt:1-4`) is a per-file copyleft requiring source disclosure for every OpenGrok file Specera modifies (§3.1, `:156-167`), it is `INFERENCE` GPL-incompatible so it poisons the wider dependency choice, it fixes California venue on Specera (`:381-387`), and six further bundled licenses (`LICENSE-adaic.org.txt`, `-eclipse`, `-ecma`, `-mandoc`, `-ruby`, `-scala`) mean a vendoring decision is a per-file audit rather than one call. Even setting license aside, the technical fit is wrong: the product of indexing is a Lucene document plus a **static HTML page** (`index/IndexDatabase.java:1184-1200`), and the "cross-reference" is a search-query hyperlink (`analysis/JFlexXrefUtils.java:264-293`) — there is no machine-consumable graph for Specera to build on, so integrating it would buy a UI Specera does not want and none of the structure it does. [Zoekt](zoekt.md) is Apache-2.0 and strictly better as the lexical layer. What Specera should take is the *idea*, which is free: per-analyzer version stamps in the index (`:2309-2317`), the sorted merge-join reconciliation (`:1759-1830`), VCS-history-driven change-set collection (`:906-933`), and the pending-file two-phase commit — all reimplementable from the design without touching a line of CDDL code.
