# GitNexus Enterprise (Akon Labs)

The paid tier Akon Labs (YC S26) sells on top of the PolyForm-Noncommercial `gitnexus` engine: managed SaaS at $29/seat or self-hosted/air-gapped, adding automated PR review with blast-radius analysis, auto-reindexing, a unified multi-repo graph, and a commercial licence for the OSS code itself.

## 1. Verdict

**A paid product demonstrably exists** — this was re-verified independently, not taken on trust: there is a public price ($29/seat), a live app at `app.akonlabs.com`, an enterprise page, a security page, and a company (Akon Labs, YC S26). It is a competitor to one slice of Specera (PR review + code knowledge), not to the platform. The single thing it does better than anything else is **open-core done honestly at the licence layer**: PolyForm Noncommercial 1.0.0 means the OSS engine is free for individuals and unusable by any company without buying a licence, so the 44,995-star distribution converts directly into a sales funnel rather than into free enterprise usage. What kills it as a threat: **the published feature gating is measurably wrong**. The pricing page sells "multi-repo unified graph" as an Enterprise feature and credits the OSS tier with "7 MCP tools" and "13 languages", while the OSS repo at HEAD `9eaf2e6c` ships **17 MCP tools**, **14 languages**, and cross-repo groups with contract-bridged edges that landed in OSS v1.5.0 on 2026-04-19. `INFERENCE` The enterprise differentiator is therefore mostly *hosting, freshness automation, and the licence* — not capability. There are **no compliance certifications of any kind**, no customer names, and no DPA.

`FACT` The OSS engine is covered by another agent under `docs/spike/competitors/gitnexus.md`. This file covers only the commercial layer and the OSS/paid boundary. Do not duplicate.

## 2. Core architecture and unique mechanism

No access to the enterprise codebase. Everything below is either read from the OSS repo (which the paid tier is built on) or from Akon Labs' public pages, labelled accordingly.

**The paid tier is the OSS engine plus hosting.** `VENDOR CLAIM` (https://akonlabs.com/enterprise, fetched 2026-08-04) — "one graph across every repo. Every agent, every pipeline, every team", offered under three trust models: managed SaaS, self-hosted VPC/on-prem, and air-gapped "zero egress, fully offline operation". `INFERENCE` Since the OSS engine already runs fully locally with no external calls, "air-gapped" is not an engineering achievement of the paid tier — it is the OSS default, resold. Basis: https://akonlabs.com/security states "GitNexus makes zero external calls by design" and "Everything GitNexus knows sits in a `.gitnexus/` folder next to your code."

**What the paid tier actually adds**, per the README's own Enterprise section (`README.md:915-930`, HEAD `9eaf2e6c`), verbatim:
- "**PR Review** — automated blast radius analysis on pull requests"
- "**Auto-updating Code Wiki** — always up-to-date documentation (Code Wiki is also available in OSS)"
- "**Auto-reindexing** — knowledge graph stays fresh automatically"
- "**Multi-repo support** — unified graph across repositories"
- "**OCaml support** — additional language coverage"
- "**Priority feature/language support**"
- "**Upcoming:** auto regression forensics · end-to-end test generation"

`FACT` Two of these six are already in OSS, verified from the clone:
1. **Multi-repo is in OSS.** `AGENTS.md:102` records "2026-04-19 | 1.5.0 | Cross-repo impact (#794): `impact`/`query`/`context` accept `repo: \"@<group>\"` + `service`"; `ARCHITECTURE.md:67` maps "Cross-repo groups (sync, contracts, `@<group>` routing)" to `src/core/group/` (`service.ts`, `cross-impact.ts`, `sync.ts`, `bridge-db.ts`); the OSS skill doc documents `group_list` and `group_sync` and a cross-repo trace that "may cross **one** `ContractLink` boundary". The pricing page nonetheless lists "multi-repo unified graph" only under the $29/seat tier.
2. **Auto-reindexing is partly in OSS.** `README.md:218` — Claude Code and Codex get "PostToolUse hooks that detect a stale index after commits and prompt the agent to reindex", and the MCP layer stamps a staleness field whose "presence is the signal" (`gitnexus-claude-plugin/skills/gitnexus-guide/SKILL.md:94`). `INFERENCE` OSS detects staleness and asks; Enterprise presumably re-indexes without asking. That is a scheduler, not an algorithm.

**PR review — the one enterprise feature with real engineering, and it is visible in the OSS repo.** `FACT` `.github/workflows/gitnexus-review-agent.yml` is a **2,746-line** GitHub Actions workflow at HEAD `9eaf2e6c`, depending on the pinned OSS package (`.github/gitnexus-review-runtime/package.json` → `"gitnexus": "1.6.9"`) plus a `CLAUDE_CODE_OAUTH_TOKEN`. Its header comment states the design outright: "untrusted PR data is analyzed in a read-only job and crosses into a separate, secretless publisher only as a bounded JSON artifact." Verified mechanisms in the file:
- `permissions: {}` at workflow level, with each job granted the minimum (line 35 and per-job blocks).
- `persist-credentials: false` on checkouts (lines 311, 324).
- The analysis lanes run under **Bubblewrap** (`sudo apt-get install --yes --no-install-recommends bubblewrap`, line 376) with `--unshare-user --unshare-pid --unshare-net` (lines 389-391, 462-465, 556-559, 636-638, 682-684, 835-837) — i.e. **the model-driven analysis runs with the network namespace removed**.
- Comment trigger is behind a repository variable (`GITNEXUS_REVIEW_COMMENT_ENABLED`), default off, and restricted to `OWNER`/`MEMBER`/`COLLABORATOR` author associations (lines 44-51).
- Third-party actions pinned to exact SHAs (e.g. `actions/github-script@3a2844b7…`).

`INFERENCE` This is the **best prompt-injection containment design found anywhere in this competitive spike**, and it is the single most valuable artefact in this file. The threat it defeats is concrete: a fork PR whose diff or description tries to steer the reviewing agent into exfiltrating secrets. Splitting privilege (analyser has no write scope and no network; publisher has no model credential; the only channel between them is a bounded JSON artifact) makes exfiltration structurally impossible rather than prompt-dependent.

`UNVERIFIED` Whether the hosted Enterprise PR review is this same workflow productised, or a separate closed service. To verify: obtain an Enterprise trial and inspect the GitHub App's requested scopes and the review job's egress. `INFERENCE` The workflow's existence in the public repo, pinned to the public npm package, suggests the paid version is the same pipeline run as a service.

**Distribution and cadence — verified independently.** `FACT` npm registry (fetched 2026-08-04): package `gitnexus`, **729 published versions**, first `1.0.0` on 2026-02-06, last modified 2026-08-03; dist-tags `latest: 1.6.9`, `rc: 1.6.10-rc.153`, and an unusual third tag **`aptos: 1.6.10-aptos.2`**. `INFERENCE` A named vendor-specific dist-tag alongside `latest`/`rc` implies a bespoke build for a named counterparty (Aptos) — the closest thing to evidence of a real commercial engagement found, though the relationship is unstated. To verify: ask Akon Labs, or find an Aptos-side announcement. `FACT` Downloads: 55,110 in the week ending 2026-08-02; 249,440 in the 30 days ending 2026-08-02 (api.npmjs.org). `FACT` GitHub: 44,995 stars, 4,986 forks, created 2025-08-02, pushed 2026-08-04, 280 open issues, not archived (api.github.com). `FACT` Release cadence is extreme — 729 npm versions in ~6 months, and an `rc` line at build 153.

`INFERENCE` The RC/canary tag structure, a 2,746-line hardened review workflow, cosign image signing with a Kubernetes admission policy (`README.md`, cluster-image-policy section), an OpenSSF Scorecard badge, gitleaks, CodeQL, and Trivy workflows together indicate a release-engineering discipline well above what a pre-revenue project needs. Repo at HEAD `9eaf2e6c`: `README.md:138` says "**17 MCP tools (15 per-repo + 2 group)**"; the supported-languages table at `README.md:541` lists **14** (TypeScript, JavaScript, Python, Java, Kotlin, C#, Go, Rust, PHP, Ruby, Swift, C, C++, Dart); cross-repo groups shipped in OSS v1.5.0 on 2026-04-19. The enterprise page separately claims "17+ languages". `INFERENCE` Three different language counts across two vendor pages and the repo. The marketing is stale relative to a repo shipping 729 npm versions in six months — but a buyer comparing tiers is being shown a false gating, and a competitor can demonstrate it in one command.

That works for a security-conscious engineer and fails a regulated procurement review — the identical gap Graphify Platform has.
- `FACT` **No named customer anywhere.** No logo wall, no case study, no customer quote on akonlabs.com; the only testimonial found is "a solo developer using GitNexus for Neura, 51+ subsystems". ## 6. Security, deployment, and license

**Pricing model** `FACT` (https://akonlabs.com/pricing, fetched 2026-08-04): three tiers — Open Source "$0 forever"; **Enterprise (Managed SaaS) "$29/seat"**; Self-Hosted Enterprise, custom, contact required. Per-seat, not usage-metered — notably against the grain of Augment ($100/mo of consumption) and Greptile (credits per review). **No self-host price is public; do not estimate.** `FACT` A third-party research page dated June 2026 (https://rywalker.com/research/gitnexus) states "no public price list yet" — so the $29/seat figure was published between June and August 2026. Recency matters here; re-check before quoting.

**Deployment** `VENDOR CLAIM` (https://akonlabs.com/enterprise): three trust models — managed SaaS, self-hosted VPC/on-prem, and air-gapped with "zero egress, fully offline operation". Plus "SSO & access controls" per the customer's identity provider and "CI/CD integration" with impact gates.

**Data residency** `INFERENCE`: for self-hosted and air-gapped, residency is the customer's own infrastructure — the OSS engine writes everything to a local `.gitnexus/` directory and makes "zero external calls by design" (https://akonlabs.com/security). `UNVERIFIED` For the managed SaaS tier, **no region, cloud provider, or residency statement is published anywhere**. To verify: ask Akon Labs, or inspect `app.akonlabs.com` hosting.

**Training on customer code** `FACT`: the security page states "We never see your source. There is no phone-home, no snippet sampling, no usage payloads carrying code." `INFERENCE` For local/self-hosted use this is structurally true, not merely promised. `UNVERIFIED` There is **no written no-training policy, no DPA, and no terms page covering the managed SaaS tier**, where code necessarily is received. Absence of a policy is not a policy.

**Compliance** `FACT`: **none claimed.** No SOC 2, ISO 27001, ISO 42001, GDPR, HIPAA, or FedRAMP statement on https://akonlabs.com/security or anywhere on the site; `akonlabs.com/docs` and `/customers` 404.

**Telemetry caveat** `FACT`: the published npm package depends on `@scarf/scarf` (npm registry, `gitnexus@1.6.9` dependency list, fetched 2026-08-04) — Scarf is an install/usage analytics package. `INFERENCE` This is package-level install telemetry, which is *not* contradicted by "no usage payloads carrying code", but it does contradict a naive reading of "no phone-home". **Prompt injection** `FACT` — and this is the vendor's strongest security work: the PR review pipeline runs untrusted PR content through Bubblewrap-sandboxed jobs with `--unshare-user --unshare-pid --unshare-net`, `permissions: {}` at workflow scope, `persist-credentials: false`, exact-SHA action pinning, a default-off comment trigger gated to OWNER/MEMBER/COLLABORATOR, and a secretless publisher job that receives only "a bounded JSON artifact" (`.github/workflows/gitnexus-review-agent.yml`, HEAD `9eaf2e6c`).

**Licence** `FACT`, verified from the repository and not from memory: **PolyForm Noncommercial 1.0.0**, `.spike/clones/GitNexus/LICENSE:1`, text beginning "PolyForm Noncommercial License 1.0.0 / <https://polyformproject.org/licenses/noncommercial/1.0.0>". `INFERENCE` **Reuse implications for Specera, and they are absolute.** PolyForm NC permits use only for "noncommercial purposes"; Specera is a commercial product, so *nothing* in this repository may be copied, vendored, forked, linked, or run as part of Specera — including the CLI, the graph engine, the Claude plugin, and the 2,746-line review workflow YAML — without a paid commercial licence from Akon Labs. ## 7. Ideas to adopt or avoid

### Adopt
- **Split-privilege agentic PR review (clean-room reimplementation).** Specera's review runner should be two jobs: an analyser that has read-only repo scope, no write token, no model-provider secret beyond what it needs, and **no network namespace**, emitting a schema-bounded JSON verdict; and a publisher that holds the write token, has no model access, and can only render that JSON. Untrusted PR text then cannot reach anything that can act. Pattern source: `.github/workflows/gitnexus-review-agent.yml` (do not copy the file — PolyForm NC).
- **Run model-driven analysis with the network unshared.** `--unshare-net` on the analysis sandbox turns "the agent might exfiltrate" into "the agent cannot reach anything". Cheap, verifiable in CI, and a one-line answer to the most common security objection to AI review.
- **Ship the review trigger default-off behind a repository variable, gated on author association.** A staged-rollout checklist embedded in the workflow header (verify same-repo PR, then fork PR, then flip the variable; roll back by flipping it back) is a deployment pattern Specera should copy for every agent that can comment on a PR.
- **Index-staleness as a first-class field in every tool response.** GitNexus stamps a freshness marker whose "presence is the signal" and its agent skill instructs the model to re-index before trusting blast-radius answers. Specera should make every retrieval response self-declare whether the graph is behind the working tree — it converts a silent correctness failure into a visible one.
- **Sell token savings, not solve rate.** "30% fewer tokens at identical solve rate — 116/162 solved by both, −47.4M tokens, −931 API calls" is a defensible claim shape that maps to a line item the buyer already sees on an invoice. Specera should instrument and publish the same metric, with the harness open.
- **Cosign keyless signing plus a Kubernetes `ClusterImagePolicy` that rejects unsigned images at admission.** For a self-hosted enterprise product this is the supply-chain control buyers actually ask for, and it is a differentiator against every competitor here that ships only a Docker tag.

### Avoid
- **PolyForm Noncommercial for anything Specera wants embedded.** It converts stars into leads but blocks corporate laptops, chills employee contribution, and prevents any downstream vendor from building on the format. If Specera open-sources a graph format, permissive-plus-paid-services beats non-commercial-plus-licence-sales for a format play.
- **Selling features the free tier already ships.** Multi-repo is in OSS v1.5.0 and on the paid pricing page. Any competitor can prove this in one command, and it destroys trust in the rest of the tier comparison.
- **Letting the marketing page drift from the repo.** Three different language counts (13 / 14 / 17+) and two MCP tool counts (7 / 17) across two vendor pages and one README. Specera should generate its capability matrix from the code.
- **An enterprise tier whose support channel is a founder's email and a Discord invite,** with no DPA, no subprocessor list, and a 404 on `/docs` and `/customers`.
- **Shipping install telemetry (`@scarf/scarf`) while the security page says "no phone-home".** Either remove it or disclose it prominently; a security reviewer will find it in the dependency tree.

## 8. Build, borrow, buy, integrate, or reject

**Reject.** The licence makes this binary: PolyForm Noncommercial 1.0.0 (`LICENSE:1`) forbids any commercial use, so Specera cannot build on, borrow from, or vendor a single line — buying a commercial licence would mean paying Akon Labs to depend on a two-page-company's engine for Specera's core substrate, which inverts the strategic position. Integration is equally unattractive: the product covers only two of eleven SDLC stages, has no tracker integration, and its own roadmap points at testing rather than at requirements or release. `INFERENCE` The right posture is to **clean-room reimplement the two mechanisms worth having** — split-privilege network-unshared PR review, and staleness-stamped retrieval responses — and to compete on the gaps: certifications (they have none), a documented managed-tier data policy (they have none), and the requirements/Jira/release stages (they have none). Watch the `aptos` npm dist-tag and the "upcoming" e2e-test-generation feature as leading indicators of where Akon Labs goes next.
