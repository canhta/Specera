# Augment Code

A closed-source SaaS that keeps a per-tenant semantic index of an org's repositories ("Context Engine") and drives fleets of specialised agents ("Cosmos Experts") off it — ticket intake, planning, PR authoring, PR review, E2E testing, CVE remediation, and incident response.

## 1. Verdict

**This is the most direct and most dangerous competitor to Specera in this file set** — more so than any graph-retrieval tool, because Augment is not selling retrieval, it is selling the SDLC loop itself. `FACT` The homepage headline as of 2026-08-04 is "The Agentic SDLC Platform for Loops" (https://www.augmentcode.com/), and the named loops are code review, ticket-to-PR, vulnerability remediation, and incident response — four of Specera's eleven stages, with requirements handled as a "living spec" in a fifth product (Intent). The single thing it does better than anything else is **shipping measured production outcomes rather than capability claims**: it publishes MTTR, time-to-first-RCA, PR-acceptance and review-precision numbers from its own engineering org (§3). What kills it, for a buyer: **every one of those numbers is self-reported by the vendor with no third-party audit and no published harness**, the retrieval architecture is a black box (no engineering post names the index structure beyond "semantic"), and there is no self-hosted deployment — it is SaaS or customer-cloud-managed, never air-gapped.

`INFERENCE` Specera cannot win on breadth against Augment. The openings are: verifiable provenance of retrieval, true self-host/air-gap, and the requirements/architecture stages (PRD, ADR, Gherkin) that Augment touches only as an informal "spec".

## 2. Core architecture and unique mechanism

No source access. Everything below is from vendor docs and vendor engineering posts, labelled accordingly.

**The index.** `FACT` The most technically specific public document is the security engineering post (https://www.augmentcode.com/blog/securing-the-code-that-writes-code-a-look-inside-our-ai-platform, dated 2025-02-03, last updated 2026-06-18, fetched 2026-08-04). It states file contents are identified by "calculating its unique SHA256 hash" and "stored in Google Cloud Bigtable, a low latency scale-out NoSQL database", behind a "transparent bigtable proxy which will validate each read and write operation". It names a **"per-tenant index"** and refers to a **"retrieval embedding file"** in the context of access-control validation.

`INFERENCE` From those three phrases: the Context Engine is a **content-addressed blob store (SHA256 → Bigtable) plus per-tenant embedding-based retrieval**, i.e. a vector/semantic index, not a code graph. Basis: "retrieval embedding file", "semantically indexes", "per-tenant index", and the total absence of the words graph, AST, tree-sitter, or call-edge from every Augment page fetched. This is the decisive architectural difference from Graphify/GitNexus: **Augment is embeddings-first, not graph-first.**

`FACT` No Augment page fetched (`/context-engine`, `/product/context-engine-mcp`, `docs.augmentcode.com/context-services/mcp/overview`) discloses the embedding model, vector store, chunking strategy, reranker, index size, or query latency. `/context-engine` says only that it is "not just grep or keyword matching" but "a full search engine for your code", and that it "semantically indexes and maps your code, understanding relationships between hundreds of thousands of files."

**Index freshness.** `FACT` Two indexing paths (https://docs.augmentcode.com/context-services/mcp/overview): local — "Real-time indexing of your working directory" with immediate file-change detection; remote — repositories indexed via a GitHub App, updating "when commits are pushed to the default branch". `INFERENCE` So the remote index tracks only the default branch; feature-branch state is covered only by the local path. A cloud agent reasoning about a long-lived branch is reading a default-branch index plus a diff.

**Proof-of-Possession — the genuinely unusual mechanism.** `FACT` Rather than replicating the customer's ACL model server-side, Augment sends file fingerprints as a "request slip" so the model "only sees the code you've explicitly granted it access to"; the security page calls the result a "non-extractable architecture" preventing "data exfiltration and cross-tenant leakage" (https://www.augmentcode.com/security, https://www.augmentcode.com/blog/securing-the-code-that-writes-code-a-look-inside-our-ai-platform). `INFERENCE` This is a real design idea worth stealing: authorisation is proven by possession of the content hash, so the index can be shared while access cannot leak. Internal transport is mTLS with scoped service tokens; production access is gated by an audited tool called "Genie".

**Retrieval exposed as a product.** `FACT` The Context Engine shipped as a standalone MCP server on 2026-02-06 (https://www.augmentcode.com/blog/context-engine-mcp-now-live) so third-party agents can call it; the local MCP tool is named `codebase-retrieval` (docs, fetched 2026-08-04).

**Agent layer.** `FACT` Cosmos, announced 2026-06-03 (https://www.augmentcode.com/blog/cosmos-the-platform-for-ai-native-engineering-teams), is described as "teams of agents — specialized, proactive agents that coordinate, delegate, and share memory", over "a shared virtual filesystem with system-wide and private memory" where "patterns, conventions, and corrections carry forward across sessions, agents, and teammates." `VENDOR CLAIM` Experts learn from feedback ("coaching"). Intent, announced 2026-02-10 (https://www.augmentcode.com/blog/intent-a-workspace-for-agent-orchestration), is the human workspace: "Work starts from a spec that evolves as agents make progress", each workspace "backed by an isolated git worktree".

**Retrieval honesty note.** `FACT` A founding engineer (Colin Flaherty) is quoted saying "We explored adding various embedding-based retrieval tools, but found that for SweeBench tasks this was not the bottleneck - grep and find were sufficient" (https://jxnl.co/writing/2025/09/11/why-grep-beat-embeddings-in-our-swe-bench-agent-lessons-from-augment/). `INFERENCE` Augment's own leaderboard agent did **not** rely on the Context Engine; the semantic index earns its keep on large real repos, not on SWE-bench. Anyone benchmarking Specera's retrieval on SWE-bench is measuring the wrong thing — this is a directly usable lesson.

## 3. Strongest capabilities

- `FACT` **PR review with published offline and production metrics** (https://www.augmentcode.com/blog/how-we-built-high-quality-ai-code-review-agent, last updated 2026-06-18): offline F1 53.8% (ranked #1), recall 62.8% (#1), precision 47.0% (#2); production, 1.03 bugs fixed per PR vs 0.54 for human reviewers, 45% true-positive rate vs 50% human, 3.6 comments per PR. **All self-reported, no external harness published.** Still, this is more measurement than any competitor in this set publishes.
- `FACT` Review checks four named categories — bugs, security concerns, correctness, cross-system problems (breaking changes, API compatibility, integration) — and "avoids low-value style nags" (https://docs.augmentcode.com/codereview/overview). Two styles, "Thorough" (default, `VENDOR CLAIM` "catches 50% more bugs") and "Precise". Hierarchical, directory-scoped custom guidelines.
- `FACT` **Ticket-to-PR as a named product surface** with a four-stage pipeline: Task Intake ("Picks the ticket up from Jira, Linear, or Slack and gathers linked issues, comments, designs, and prior art") → Planner ("Scopes the change against the live codebase with the Context Engine and posts a plan back on the ticket") → PR Author → Review Fleet (https://www.augmentcode.com/solutions/ticket-to-pr).
- `FACT` **Incident response is a shipped, measured loop**, not a slide (https://www.augmentcode.com/blog/scaling-incident-management-for-an-ai-native-organization-using-cosmos, 2026-05-26): agents handle 81.3% of incidents vs 0.4% pre-deployment; median time-to-first-RCA 30.1 → 6.2 min; MTTR 29.5 → 19.9 min; on-call engineers merged 44% more PRs/week. Integrations named: Slack (control plane), PagerDuty, GCP Cloud Logging, GCP Managed Prometheus, GitHub, `kubectl`. **Self-reported, measured on Augment's own engineering org, not a customer.**
- `FACT` Context Engine sold as an MCP server other agents can consume, with a stated eval: "300 Elasticsearch PRs, each with 3 different prompts, for 900 attempts total"; claimed improvements Claude Code + Opus 4.5 80%, Cursor + Opus 4.5 71%, Cursor + Composer-1 30% (https://www.augmentcode.com/blog/context-engine-mcp-now-live, 2026-02-06). `VENDOR CLAIM` — grader, rubric weighting, and raw scores are not published; "improvement" is measured against five self-defined dimensions.
- `FACT` Benchmarks, both **self-reported**: SWE-bench Verified 65.4% (Claude Sonnet 3.7 driver + OpenAI o1 ensembler), agent open-sourced at https://github.com/augmentcode/augment-swebench-agent; SWE-bench Pro 51.80% with Claude Opus 4.5 (https://www.augmentcode.com/blog/auggie-tops-swe-bench-pro, 2026-02-04), where the SWE-Agent comparison baseline is taken from Scale AI's leaderboard but "all other evaluations run by Augment Code using identical harness."
- `FACT` Enterprise trust surface actually exists: SOC 2 Type II, ISO/IEC 42001, GDPR, CCPA, HIPAA, BAA available (https://www.augmentcode.com/security). This is exactly what Graphify Platform lacks.

## 4. Critical weaknesses

- `FACT` **The retrieval architecture is undisclosed.** Across `/context-engine`, `/product/context-engine-mcp`, and the MCP docs, no embedding model, vector store, chunker, reranker, index size, or latency figure appears. `INFERENCE` A buyer cannot assess recall failure modes, and cannot tell whether cross-repo "relationships" are computed or merely co-embedded. Specera's provenance story attacks this directly.
- `INFERENCE` **No code-graph, therefore no deterministic edges.** Basis: "retrieval embedding file" is the only index primitive ever named; no page fetched contains "AST", "tree-sitter", "call graph", or "dependency graph". An embedding index cannot answer "every caller of this function, exhaustively" — it answers "things that look related." For impact analysis at a merge gate this is a materially weaker substrate than a parsed graph.
- `FACT` **Every headline number is self-reported.** SWE-bench Pro, the 70%+ MCP uplift, the code-review F1/precision, the 81% incident reduction, the ticket-to-PR figures (67% more merged PRs/engineer/day, 82% agent PR acceptance, backlog 14.5 → 30.7 tickets/week, small fixes 18 h → 9 min) — all from augmentcode.com, none audited, several measured on Augment's own internal engineering org rather than a customer.
- `FACT` **Code Review is GitHub-only in the docs.** https://docs.augmentcode.com/codereview/overview describes only GitHub App connection; GitLab and Bitbucket are not mentioned. (The ticket-to-PR solutions page does mention GitLab in an audit-log context — `UNVERIFIED` whether review runs on GitLab. Verify by finding a GitLab setup doc.)
- `FACT` **No self-hosted or air-gapped deployment.** The security page names SaaS with customer-managed encryption keys; no on-prem/air-gap option appears anywhere fetched. `INFERENCE` Defence, classified, and some financial buyers are excluded — a durable gap Specera can occupy.
- `INFERENCE` **Remote index tracks only the default branch** (docs, above). Long-lived branches and stacked PRs are served by a stale-by-design remote index plus local re-indexing.
- `UNVERIFIED` **Inline completions were removed from lower tiers on 2026-03-31** for Indie/Standard/Legacy plans, per a third-party post (https://www.bodegaone.ai/blog/augment-code-sunset-completions-what-next). No first-party changelog confirming this was fetched. If true it signals a hard pivot from IDE assistant to agent platform. To verify: find Augment's own changelog entry or plan-migration email.
- `UNVERIFIED` **Customer names are inconsistent across pages.** The homepage logo strip lists Adobe, MongoDB, Pure Storage, DXC, DDN, Tekion, Snyk, MoneyGram, Crypto.com, Webflow, Pigment; the Cosmos launch post's fetched summary referenced Stripe, Ramp, and Uber as examples. `INFERENCE` The latter are likely illustrative rather than customers. No first-party customer case study with a named engineering leader was verified. To verify: find a customer-bylined post.
- `UNVERIFIED` **Company financials.** Secondary aggregators (PitchBook, Tracxn) report ~$252M raised, ~$20M revenue, ~156 employees, ~$1B valuation. None of this is first-party and none was fetched from a primary filing. Treat as rumour. **The company is not shut down and not acquired** as of 2026-08-04 — the site is live and posting product updates through June 2026.
- `INFERENCE` **Prompt-injection surface is wide and undocumented.** Cosmos ingests Jira/Linear tickets, Slack threads, PR comments, PagerDuty alerts, and production logs, then hands them to agents holding `kubectl` and GitHub write access. No page fetched documents an injection control, a trust boundary between ticket text and agent instruction, or a privilege model for the incident Experts. This is the single sharpest technical criticism available.

## 7. Ideas to adopt or avoid

### Adopt
- **Proof-of-Possession authorisation.** Specera should authorise retrieval by content hash the caller can already prove it holds, instead of mirroring the customer's repo ACLs into its own index. It makes cross-tenant leakage structurally impossible rather than policy-dependent, and it removes an entire class of permission-sync bugs. Source: https://www.augmentcode.com/blog/securing-the-code-that-writes-code-a-look-inside-our-ai-platform.
- **Publish review-quality metrics as F1/precision/recall against a labelled bug set, plus a production true-positive rate.** Augment's 53.8% F1 / 47.0% precision / 45% production TPR is the bar. Specera should build that eval harness before the review feature, not after — and, unlike Augment, publish the harness so the number is checkable. Source: https://www.augmentcode.com/blog/how-we-built-high-quality-ai-code-review-agent.
- **Two review styles ("Thorough" / "Precise") plus directory-scoped guidelines.** Comment volume is the #1 reason teams turn AI review off; making verbosity a first-class setting and scoping guidelines per directory tree is cheap and directly addresses it. Source: https://docs.augmentcode.com/codereview/overview.
- **"Post the plan back on the ticket" before implementing.** The Planner writes its scoped plan into Jira as a comment, so the human checkpoint happens in the tracker the team already watches, not in a separate tool. This is the cheapest possible trust mechanism for ticket-to-PR. Source: https://www.augmentcode.com/solutions/ticket-to-pr.
- **Ship retrieval as a standalone MCP server.** Augment monetises the Context Engine independently of its agents, which turns competitors' agents (Claude Code, Cursor) into distribution. Specera's graph should be consumable the same way from day one. Source: https://www.augmentcode.com/blog/context-engine-mcp-now-live.
- **Do not tune retrieval on SWE-bench.** Augment's own founding engineer says grep and find sufficed there. Specera should build an eval on large multi-repo change sets (Augment used 300 Elasticsearch PRs × 3 prompts = 900 attempts) instead. Source: https://jxnl.co/writing/2025/09/11/....
- **Consumption pricing with seats bundled free.** "$100/month flat, up to 50 seats, $100 of usage included" reframes the buy as compute, not headcount. Source: https://www.augmentcode.com/pricing.

### Avoid
- **Selling "semantic understanding" while disclosing nothing about the index.** It works for Augment because they have SOC 2 and logos; it will not work for a challenger. Specera's wedge is the opposite: name the mechanism, tag the provenance.
- **Embeddings as the only retrieval substrate.** It cannot answer exhaustive-caller or transitive-impact questions soundly, which is exactly what a merge gate needs.
- **Benchmarking against yourself with an unpublished harness.** Every Augment number is "run by Augment Code using identical harness". Specera should publish the harness or not publish the number.
- **Wiring agents to `kubectl` and repo-write while ingesting ticket and Slack text with no documented injection boundary.** Whatever Specera ships for incidents must have an explicit trust boundary between untrusted narrative text and tool authorisation.
- **Indexing only the default branch remotely.** Long-lived branches are where enterprise change actually lives.

## 8. Build, borrow, buy, integrate, or reject

**Reject as a vendor, borrow the mechanisms, and treat it as the primary competitive benchmark.** There is nothing to buy or integrate — it is closed SaaS, proprietary, with no self-host, and it competes for the same budget line Specera targets. `INFERENCE` The strategic read: Augment has already won breadth (6/11 stages Yes) and has the compliance posture (SOC 2 Type II, ISO 42001) that Graphify lacks, so Specera cannot out-feature it. Specera's defensible differences are (a) a deterministic, provenance-labelled graph substrate versus an undisclosed embedding index, (b) genuine self-host/air-gap, and (c) the front half of the SDLC — structured PRD, ADR, and Gherkin/acceptance-criteria traceability — where Augment has an informal "living spec" and nothing else. License is irrelevant here: nothing is reusable as code.
