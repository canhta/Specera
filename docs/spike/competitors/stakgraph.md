# StakGraph (stakwork/stakgraph, unlicensed source-available)

A Rust workspace (`ast/`, `lsp/`, `standalone/`, `skill/`, plus a TypeScript `mcp/` server and a Go `gateway/`) that tree-sitter-parses 16 languages into a 21-node-type / 13-edge-type Neo4j graph whose vocabulary is **product-shaped** (`Endpoint`, `Request`, `DataModel`, `Page`, `UnitTest`, `IntegrationTest`, `E2eTest`, `Mock`, `Concept`), links frontend `Request` nodes to backend `Endpoint` nodes **across repositories**, and optionally augments tree-sitter with real LSP servers for goto-definition and goto-implementations.

## 1. Verdict

`FACT` StakGraph ships **no LICENSE file at all** at HEAD `847d7cdc` — no `LICENSE`, `LICENCE`, or `COPYING` at the repository root; the only licence file in the tree is `gateway/auth/ts/LICENSE` (MIT, © 2026 Stakwork), scoped to the separately-published `gatekey` npm package. `INFERENCE` Default copyright therefore reserves all rights: the code is readable but **not reusable, forkable, or vendorable without written permission from Stakwork**, and the fact that a sub-package has its own MIT file establishes that the omission is not ignorance of licensing. That single fact removes borrow, fork and integrate from the option set regardless of technical merit. `FACT` The technical merit is nonetheless the highest in this comparison on two axes: it is the only tool here that emits **cross-repository service edges** (`Request → Endpoint` matched on normalised path + HTTP verb, `ast/src/lang/linker.rs:362-393`), and the only one with a **hand-authored ground-truth accuracy harness** — 3,643 `@ast node:` / `@ast edge:` annotations written into 391 fixture files and verified by a test that panics on any mismatch (`ast/src/testing/annotations.rs:455-481`). `FACT` The tree-sitter + LSP combination is real but narrow: LSP is off unless `USE_LSP=true`, and even then it activates for only Rust, Go, TypeScript and Java (`lsp/src/language.rs:168-175`).

## 2. Core architecture and unique mechanism

**Workspace layout.** `FACT` `Cargo.toml` declares members `["ast", "lsp", "shared", "skill", "standalone"]`; alongside them sit `mcp/` (TypeScript MCP server + agents), `gateway/` (Go), `cli/` (separate crate), `vein/` (TypeScript workflow/eval engine), `treesitter/` (a readme only). ~56,800 lines of Rust across the workspace.

**Node types — 21** (`ast/src/lang/graphs/mod.rs:31-56`):
`Repository, Package, Language, Directory, File, Import, Library, Class, Trait, Instance, Function, Endpoint, Request, DataModel (serialised "Datamodel"), Concept (alias "Feature"), Page, Var, UnitTest, IntegrationTest, E2eTest, Mock`.

**Edge types — 13** (`ast/src/lang/graphs/mod.rs:83-98`), with the authors' own comments:
`Calls` (Function→Function), `Uses` (like Calls but for libraries), `Operand` (Class→Function), `ArgOf` (Function→Arg), `Contains` (Module/File→Function/Class/Module), `Imports` (File→Module), `Of` (Instance→Class), `Handler` (Endpoint→Function), `Includes` (Concept→Function/Class/Module/Endpoint/Request/DataModel/Test), `Renders` (Page→Component), `ParentOf` (Class→Class), `Implements` (Class→Trait), `NestedIn` (Function→Function, child to parent).

`INFERENCE` This is the most SDLC-shaped schema in the set. `Endpoint`/`Request`/`Handler` make service topology expressible; `UnitTest`/`IntegrationTest`/`E2eTest`/`Mock` plus `Includes` make "which tests cover this feature" a graph query rather than a heuristic; `Concept`/`Feature` gives a place to attach product-level meaning. `FACT` Edges carry `ref_id` (a UUID) and an optional `operand` string (`mod.rs:71-78`) — plus `confidence: f32` and `strategy: String` on call edges (below).

**Parser strategy — tree-sitter first, LSP as an opt-in overlay, per-language type registries in between.**
- `FACT` tree-sitter is the base for all 16 declared languages. `Language` enum: `Bash, Toml, Rust, Go, Typescript, Python, Ruby, Kotlin, Swift, Java, Svelte, Angular, C, Cpp, Php, CSharp` (`lsp/src/language.rs:6-23`), of which `PROGRAMMING_LANGUAGES` is 14 (Bash and Toml excluded, `:25-40`). Per-language tree-sitter query files live in `ast/src/lang/queries/` (`react_ts.rs` 1674 lines, `rust.rs` 1263, `ruby.rs` 885, `php.rs` 789, `python.rs` 589, `angular.rs` 581, `go.rs` 566, `csharp.rs` 494, …).
- `FACT` **LSP is default-off and covers four languages.** `Language::default_do_lsp()` returns `false` unless the `USE_LSP` env var is `"true"`/`"1"`, and even then `matches!(self, Rust | Go | Typescript | Java)` (`lsp/src/language.rs:168-175`). `ast/src/utils.rs:138-147` (`get_use_lsp`) defaults to `"false"`. `FACT` The LSP client speaks `DidOpen`, `GotoDefinition`, `GotoImplementations`, `Hover`, `Stop` (`lsp/src/lib.rs:35-41`) against `rust-analyzer`, `gopls`, `typescript-language-server`, `pylsp`, `ruby-lsp`, `kotlin-language-server` (`lsp/src/language.rs:181-200`). `FACT` **Java is internally contradictory**: `default_do_lsp()` enables Java, but `lsp_exec()` returns `""` for Java, so `has_lsp_support()` is false — the flag turns on a server that is not named. `INFERENCE` Python, Ruby and Kotlin have named LSP binaries that `default_do_lsp` can never enable, so those three entries are dead configuration.
- `FACT` A third layer sits between: per-language **type registries** in `ast/src/lang/registry/` implementing `trait Registry { resolve_type(file, var_name), resolve_method(type_name, method_name), resolve_field(...), resolve_call_at(file, row, col) }` (`registry/mod.rs:26-34`), built for TypeScript, Python, Go, Rust, Java, C#, Kotlin, Swift, PHP (`registry/mod.rs:36-52`). `INFERENCE` Ruby, C, C++, Svelte, Angular, Bash and TOML get **no registry** — their calls fall through to pure name-based matching.
- `FACT` The Java registry is representative (`registry/java_registry.rs:25-88`): pass 1 indexes `Function` nodes per directory for same-package bare-name fallback; pass 1.5 extracts class field types and method return types from the AST; pass 2 pre-resolves every call site into `(file, row, col) → NodeKeys`. Real local type inference, no compiler.

**Call resolution — an 8-strategy ladder with a persisted confidence and strategy name** (`ast/src/lang/call_finder.rs:40-127`, `ast/src/lang/parse/format.rs:1224-1226`):

| Order | Strategy | Confidence | Rule |
|---|---|---|---|
| 0 | `type_resolved` | 1.00 | registry resolves the operand's type, then the method's defining file |
| 1 | `global_unique` | 0.90 | exactly one `Function` node repo-wide with that name |
| 2 | `same_file` | 0.85 | a function of that name in the calling file |
| 3 | `import` | 0.80 | resolved through the file's parsed imports |
| 4 | `same_dir` | 0.45 | a function of that name in the same directory |
| 5 | `operand` | 0.70 | operand-based lookup |
| 6 | `nested_var` | 0.60 | function nested in a variable |
| — | `member_expr` | 0.35 | fallback: resolve the *base object* instead of the method (`format.rs:1205-1224`) |

`FACT` **The ladder is not ordered by confidence.** `same_dir` at 0.45 is attempted *before* `operand` at 0.70 and `nested_var` at 0.60 (`call_finder.rs:94-122`). `INFERENCE` A same-directory name collision therefore pre-empts two strictly more reliable strategies, and the recorded confidence tells you the strategy that fired, not that no better one was available.

`FACT` **Strategy 1 (`global_unique`) is name-only matching, gated on global uniqueness** (`call_finder.rs:246-286`): collect every `Function` node named `func_name`, drop empty-bodied ones ("NOT empty functions (interfaces)"), drop the call site itself; if exactly one remains, that is the target. If more than one remains it retries after filtering out any file whose path contains `"mock"`, and accepts if that leaves one. `FACT` For TypeScript only, the heuristic is skipped when an operand is present, with an in-source rationale: "For strict languages (TypeScript), skip the 'find only one' heuristic when an operand exists to avoid false positives with method calls" (`:257-261`). `INFERENCE` The false-positive risk the comment names is real for every other language too, and is not mitigated for them.

`FACT` **Unverified calls are opt-in and off by default.** When nothing resolves and `allow_unverified_calls` is true, the target becomes `NodeKeys::new(&called, "unverified", row)` — a literal file named `"unverified"` (`format.rs:1233-1238`). Every constructor in `ast/src/repo.rs` sets `allow_unverified_calls: false` (`:309`, `:509`, `:547`). `INFERENCE` Correct default; the mechanism is a labelled sink rather than a fabricated edge.

**Interface / inheritance dispatch — implemented, but single-implementation and name-scoped.** `FACT` `java_resolver::find_method_in_class` (`registry/java_resolver.rs:205-262`) documents its own algorithm: Java functions carry no `operand` meta key, so it locates the `Class` node by name, then picks the `Function` node **in the same file whose byte-offset start is ≥ the class declaration's start**, sorted ascending, taking the first. If the name is a `Trait` (interface) instead, it walks `Implements` edges to implementing classes and searches those. `INFERENCE` Three consequences follow directly: (1) `find_nodes_by_name(NodeType::Class, class_name)` is unqualified, so two classes with the same simple name in different packages collide and the first wins; (2) `.into_iter().next()` over implementing classes means an interface with N implementations produces **one** edge to an arbitrary implementation, not N edges — the classic DI/Spring case where a `UserRepository` field has one interface and several implementations resolves to whichever the graph enumerates first; (3) method overloads collapse, because "first Function named X at or after the class start" cannot distinguish signatures.
`FACT` When LSP *is* enabled, the trait case is handled properly by the language server: on a `GotoDefinition` result that is not in the graph and not a library file, the code issues `GotoImplementations` and re-looks-up the target (`format.rs:1164-1180`, comment "handle trait match, jump to implemenetations"). `INFERENCE` This is the correct mechanism and it is exactly the thing that is off by default and limited to four languages.
`FACT` There is no DI-container resolver, no reflection handling, no message-queue or event-bus edge type in the 13.

**Cross-repository edges — the standout mechanism.** `FACT` `link_api_nodes` (`linker.rs:362-393`) collects every `Request` node and every `Endpoint` node in the graph, normalises both paths (`normalize_frontend_path` strips scheme+host and replaces `${...}` interpolations with `:param`, `:398-430`; `normalize_backend_path` rewrites `<x>`, `:x`, `{x}`, `(x)`, `[...x]`, `[x]` route params to `:param`, `:432-470`), and emits a `Calls` edge wherever `paths_match` (segment-count equality plus segment-wise comparison, with an `api`-prefix consistency rule) and `verbs_match` (exact uppercase HTTP verb equality) both hold. `FACT` The README states the intent: "Endpoints and requests are linked across repos — a `POST /api/users` endpoint in the backend connects to the `fetch("/api/users")` request in the frontend." `FACT` `link_integration_tests` (`linker.rs:34-140`) additionally links `IntegrationTest` nodes to `Endpoint` nodes both directly (test body contains the endpoint path, with HTTP verbs extracted from the body) and indirectly through called helper functions that issue `Request`s.
`INFERENCE` **The host is discarded before matching** (`:403-410` takes everything after the first `/` following `://`). A `POST https://api.stripe.com/v1/charges` in your frontend and a local `POST /v1/charges` endpoint would satisfy both predicates and produce a false service edge. The matcher is also an O(requests × endpoints) nested loop with no base-URL, environment, or ownership check.

**Storage.** `FACT` Three `Graph` implementations behind one trait (`ast/src/lang/graphs/graph.rs`): `ArrayGraph` (1117 lines) and `BTreeMapGraph` (1098 lines), both in-memory, and `Neo4jGraph` (`graphs/neo4j/`, `graph.rs` 1401 lines) gated behind the `neo4j` cargo feature. `FACT` Neo4j is the only persistent store; `docker-compose.yaml` starts Neo4j plus the server on port 7799. `FACT` Confidence and strategy reach Neo4j: `add_calls_edge_query(edge, confidence, strategy)` sets `r.ref_id`, `r.confidence`, `r.strategy` (`graphs/neo4j/queries/edges.rs:80-99`, called from `operations/batch.rs:160,183`). `FACT` Vector search uses BGE-Small-EN-v1.5 (384-dim) via fastembed with "weighted pooling [that] prioritizes function signatures" (README, Vector search). `INFERENCE` Self-hosting is straightforward operationally (Docker Compose, Neo4j, one Rust binary) — the constraint is legal, not technical.

**Incremental reindex — git-diff driven, with a hole.** `FACT` `GraphOps::update_incremental` (`ast/src/lang/graphs/graph_ops.rs:95-200`): compare the stored commit hash to the current one, get the changed file list via `check_revs_files` (git diff, `ast/src/repo.rs:932+`), collect "dynamic edges" (Hint/Prompt nodes) and muted nodes for those files so they can be restored, `remove_nodes_by_files(&absolute_files)`, then re-detect languages and rebuild **only the changed files** (`Repo::new_multi_detect(..., modified_files, revs, use_lsp)` → `build_graphs_neo4j_incremental`), then restore the dynamic and muted nodes. If the stored revision is unreachable in the current checkout it falls back to a full re-index (`:201-215`).
`FACT` `remove_nodes_by_files` is a two-phase count-then-`DETACH DELETE ... CALL { } IN TRANSACTIONS`, with a comment explaining that the previous single-transaction version "produces a lock set large enough to stall on internal locking or hit the bolt-stream timeout" for high-degree nodes (`graphs/neo4j/operations/migration.rs:31-60`).
`INFERENCE` **Inbound edges are lost.** `DETACH DELETE` on the changed files' nodes removes `Calls` edges *into* them from callers in unchanged files; only the changed files are re-parsed, so nothing recreates those inbound edges. The only restoration paths in the function are `restore_dynamic_edges` (Hint/Prompt nodes) and `restore_muted_nodes`. After N incremental syncs, the in-edge set of a frequently-edited file decays toward whatever the last full index produced minus everything since. Neither CodeGraphContext's affected-set recomputation nor an unresolved-reference retry table has an equivalent here.

**Query surface.** `FACT` Five MCP tools (`mcp/src/tools/stakgraph/`): `stakgraph_search` (fulltext or vector), `stakgraph_map`, `stakgraph_code`, `stakgraph_shortest_path`, `stakgraph_rules_files`, plus a separate Stagehand browser-automation tool family (`stagehand_navigate/act/extract/observe/screenshot/agent/logs/network_activity`). `FACT` Four LLM-backed agents ship in `mcp/`: Explore, Describe, Docs, Mocks (README, "Built-in agents"). `FACT` The `standalone` HTTP API exposes `/process`, `/sync`, `/ingest`, `/embed_code`, `/ingest_async`, `/sync_async`, `/clear`, `/status/:request_id`, `/fetch-repo(s)`, `/search`, `/tests/coverage`, `/tests/nodes`, `/tests/has` (`standalone/src/main.rs:78-116`).

## 3. Strongest capabilities

- `FACT` **A product-shaped node vocabulary.** `Endpoint`, `Request`, `DataModel`, `Page`, `UnitTest`, `IntegrationTest`, `E2eTest`, `Mock`, `Concept`/`Feature` are first-class types with dedicated edges (`Handler`, `Renders`, `Includes`) — not metadata on a generic `Function` (`graphs/mod.rs:31-98`).
- `FACT` **Hand-authored ground-truth annotations as the test corpus.** 3,643 `@ast node:` / `@ast edge:` comments across 391 fixture files (`grep -rc "@ast " ast/src/testing`), e.g. `ast/src/testing/go/client.go:3-9` declaring a `Function`, its `Request` with `[verb=GET]`, and an expected `Calls -> Endpoint "/person" "routes.go" [verb=POST]` edge. `run_fixture_test` panics with every failure listed (`testing/annotations.rs:455-481`). `FACT` `walk_and_verify` also asserts **per-node-type totals** — `"FAIL count: {:?} expected {} got {}"` (`:390-402`) — so over-extraction of nodes fails the suite, not just under-extraction.
- `FACT` **Test classification and linking as a designed feature.** `lang.classify_test(name, file, body)` assigns `UnitTest`/`IntegrationTest`/`E2eTest` per language (`graphs/mod.rs`, `Edge::from_test_call`); `link_integration_tests` connects tests to endpoints directly and through helper call chains (`linker.rs:34-140`); `/tests/coverage`, `/tests/nodes`, `/tests/has` expose it over HTTP.
- `FACT` **Framework-aware route extraction across 11 framework families** (README, Languages): React/Express/Nest, FastAPI/Django/Flask, Gin/Echo/net-http, Axum/Actix/Rocket, Rails (routes, ERB, HAML), Spring Boot, Ktor, Vapor, ASP.NET, Laravel, Angular, Svelte.
- `FACT` **Monorepo fixtures as a first-class test axis**: `ast/src/testing/monorepo/` covers turbo-ts, nx-mixed, turbo-python, rust, go, python-rust, npm-go, simple-ts (`testing/monorepo/mod.rs`, 827 lines).
- `FACT` **Confidence + strategy persisted on the call edge** in Neo4j (`neo4j/queries/edges.rs:99`), with named strategies rather than an opaque number.
- `FACT` **Gitree**: LLM extraction of `Feature`, `PR`, `Commit`, and `Clue` (patterns, conventions, gotchas, data flows) nodes from PR/commit history, linked to code entities (README, "Gitree: Feature knowledge from git history"). `INFERENCE` This is the only mechanism in the comparison that puts *why* the code is the way it is into the same graph as the code.
- `FACT` **A real eval discipline in the adjacent `vein` engine**: `vein/EVAL_SPEC.md` defines workflow → collect → score loops with a gold dataset, records "First real run (recall 0.8) — surfaced the overfitting/insight problem", and lists "Multi-repo dataset + train/val split — the real overfit fix" as todo.

## 4. Critical weaknesses

- `FACT` **No licence.** `find . -iname 'licen[sc]e*'` at HEAD `847d7cdc` returns exactly one file — `gateway/auth/ts/LICENSE`, MIT © 2026 Stakwork, belonging to the `gatekey` npm package (`gateway/auth/ts/package.json`, `"name": "gatekey"`). No root `LICENSE`, no `license` field in `mcp/package.json`, `vein/package.json`, `ast/Cargo.toml`, `standalone/Cargo.toml` or `cli/Cargo.toml`; no licence statement in `README.md`. `INFERENCE` All rights reserved by default. Reading and evaluating are fine; copying any code, vendoring a crate, forking, or shipping a derivative is not, absent a written grant. The scoped MIT file proves the maintainers license deliberately when they intend to.
- `FACT` **LSP — the differentiating half of the architecture — is off by default and covers 4 of 16 languages.** `default_do_lsp()` requires `USE_LSP=true` and then matches only `Rust | Go | Typescript | Java` (`lsp/src/language.rs:168-175`). `FACT` Java's `lsp_exec()` is the empty string, so `has_lsp_support()` is false for a language `default_do_lsp` enables. `FACT` The monorepo test asserts the consequence outright: `assert_eq!(all_endpoints.len(), 0, "Go endpoints require LSP")` (`testing/monorepo/mod.rs:668`) — a whole node type is empty for Go in the default configuration.
- `FACT` **Interface dispatch resolves to one arbitrary implementation.** `find_method_in_class` takes `.into_iter().next()` over the classes implementing a trait (`registry/java_resolver.rs:255-259`). `INFERENCE` For the DI-heavy Java/Spring codebases the schema is otherwise well suited to, an interface with three implementations produces one edge and two silent misses — and the one edge may be to the test double, since nothing filters implementations by wiring.
- `FACT` **Method-within-class resolution is a byte-offset heuristic.** "find the Function node in the same file whose byte-offset start is ≥ the class node's start … taking the function closest to — but not before — the class declaration" (`java_resolver.rs:205-229`). `INFERENCE` Inner classes, anonymous classes and overload sets all break this; it silently returns the first candidate.
- `FACT` **`global_unique` is name-only matching**, applied before imports, for every language except TypeScript-with-operand (`call_finder.rs:246-286`, `:257-261`). The mitigation is a `"mock"`-substring path filter.
- `FACT` **The resolution ladder is mis-ordered relative to its own confidences**: `same_dir` (0.45) is tried before `operand` (0.70) and `nested_var` (0.60) (`call_finder.rs:94-122`).
- `FACT` **Confidence is written and never read.** `grep -rn confidence mcp/src standalone/src` returns no query-side hits — the only occurrences outside the writer are in an unrelated design doc (`mcp/src/repo/ggnn.md:44`). `INFERENCE` Same defect as CodeGraphContext: a 0.35 `member_expr` edge and a 1.00 `type_resolved` edge are traversed identically by `stakgraph_map` and `stakgraph_shortest_path`.
- `INFERENCE` **Incremental sync loses inbound edges.** `update_incremental` `DETACH DELETE`s the changed files' nodes and re-parses only those files; nothing re-parses the unchanged callers whose `Calls` edges were destroyed (`graph_ops.rs:139-180`). Only Hint/Prompt "dynamic edges" and muted nodes are explicitly restored.
- `INFERENCE` **`Request → Endpoint` matching ignores the host.** `normalize_frontend_path` discards scheme and authority (`linker.rs:403-410`), so an outbound call to a third-party API whose path shape and verb coincide with one of your own routes yields a false service edge. There is no base-URL, environment, or service-ownership predicate.
- `FACT` **The graph-implementation parity test cannot fail.** `compare_graphs` iterates 12 languages and swallows every error: `if let Err(e) = compare_graphs_inner(lang, &repo_path).await { debug!("Error comparing graphs for {}: {:?}", lang, e); }` (`testing/graphs/compare_graphs.rs:26-34`).
- `FACT` **Edge annotations verify presence, not absence.** `walk_and_verify` count-checks node types but has no unexpected-edge assertion (`testing/annotations.rs:384-404`; `grep -n "unexpected\|extra"` → no matches). `INFERENCE` Edge precision is unmeasured even by the best harness in this comparison; a spurious `Calls` edge in a fixture passes the suite.
- `FACT` **The README's own architecture description conflicts with the code on LSP.** `AGENTS.md` opens "A source code parser using tree-sitter, LSP, and neo4j" and the README says only "using tree-sitter"; neither states that LSP is opt-in and four-language. `INFERENCE` A reader of either doc will overestimate resolution quality in the default configuration.
- `FACT` Install path is `curl -fsSL https://raw.githubusercontent.com/... /install.sh | bash` (README, Install). `FACT` The repo ships agent-directive files (`AGENTS.md`, `mcp/skills/`, `.ast.json`, `skill/`, `Dockerfile.skill`, `push-skill.sh`) — treated here as untrusted data, not followed.
- `FACT` The `standalone` HTTP API is **unauthenticated when `API_TOKEN` is unset**: `let Some(expected_token) = &app_state.api_token else { return Ok(next.run(request).await); }` (`standalone/src/auth.rs:19-22`). When set, comparison is constant-time via `subtle::ConstantTimeEq` (`:30-35`).

## 7. Ideas to adopt or avoid

*(Adopt here means "reimplement the idea from the specification below", not "copy the code" — the licensing forbids the latter.)*

### Adopt
- **A product-shaped node vocabulary.** Specera should make `Endpoint`, `Request`, `DataModel`, `Page`, `UnitTest`, `IntegrationTest`, `E2eTest`, `Mock` and `Feature`/`Concept` first-class node types with dedicated edges (`Handler`, `Renders`, `Includes`), exactly as `ast/src/lang/graphs/mod.rs:31-98` does. This is what makes "which tests exercise this endpoint", "what does this page render", and "what code implements this feature" single graph queries rather than heuristics — and it is the schema decision that separates an SDLC platform from a code-search index.
- **Cross-repository `Request → Endpoint` edges, done properly.** Reimplement `link_api_nodes` (`linker.rs:362-393`) with the gaps closed: keep the path-normalisation-plus-verb match, but **require a host/base-URL or service-ownership predicate** so third-party API calls cannot bind to internal routes, index endpoints by `(normalized_path, verb)` instead of the O(R×E) nested loop, and record the match basis on the edge. This is the single capability that turns a repo index into a system map.
- **Hand-authored expectations living inside the test fixtures.** The `// @ast node: Function "FetchPerson"` / `// @ast edge: Calls -> Endpoint "/person" "routes.go" [verb=POST]` convention (`ast/src/testing/annotations.rs`, 3,643 annotations in 391 files) puts ground truth next to the code it describes, so adding a fixture and adding its expectations is one edit. Specera should adopt this and go one step further than StakGraph: **also assert the absence of unexpected edges**, which converts the harness from recall-only to precision-and-recall.
- **Per-node-type total counts as a regression gate** (`annotations.rs:390-402`, `"FAIL count: {:?} expected {} got {}"`). Cheap, and it catches the over-extraction that presence-only assertions miss.
- **Named resolution strategies, not just numeric confidence** (`type_resolved`, `global_unique`, `same_file`, `import`, `same_dir`, `operand`, `nested_var`, `member_expr` — `call_finder.rs`). A strategy string on the edge is auditable in a way a float is not: "show me every edge that exists only because two functions share a name" is a `WHERE r.strategy = 'global_unique'` query. Specera should persist both — and, unlike StakGraph, filter on them by default.
- **A per-language type registry as the layer between tree-sitter and a language server** (`registry/mod.rs:26-34`: `resolve_type` / `resolve_method` / `resolve_field` / `resolve_call_at`). Field types and method return types extracted from the AST get most of the benefit of type-aware dispatch at a fraction of the cost of running a language server, and the trait boundary means a real LSP or compiler index can implement the same interface later.
- **Monorepo layouts as an explicit test axis** (`testing/monorepo/`: turbo-ts, nx-mixed, turbo-python, rust, go, python-rust, npm-go, simple-ts). Specera's target customers are monorepos; workspace-boundary resolution needs fixtures per tool, not one generic case.
- **Chunked deletion for graph writes**: `CALL { ... } IN TRANSACTIONS` instead of one large `DETACH DELETE`, with the rationale recorded in-source (`neo4j/operations/migration.rs:36-51`). Specera will hit the same lock-set blow-up on any high-degree `File` node.
- **Attenuable capability tokens for agent access** — the macaroon signer/attenuator/verifier model in `gateway/auth` (and it is MIT, so this one is genuinely reusable). An agent should hold a token narrowed to the repos and operations it needs, not a service-wide bearer.

### Avoid
- **Building on unlicensed source.** No amount of technical merit survives it. Do not vendor, fork, copy, or paraphrase-with-diff any of the Rust or TypeScript here.
- **Making the high-fidelity resolver opt-in.** LSP is the reason to combine tree-sitter with a language server, and `USE_LSP` defaults to false for all languages and is capped at four when true (`lsp/src/language.rs:168-175`). If Specera adds an LSP or compiler tier, it must be the default for every language it supports, or the schema must record which tier produced each edge so consumers can tell.
- **Declaring capability that the code contradicts.** `lsp_exec()` names servers for Python, Ruby and Kotlin that `default_do_lsp()` can never enable, and returns `""` for the Java that it does enable. A per-language capability matrix must be one table, asserted by a test.
- **Resolving interface dispatch to the first implementation.** `.into_iter().next()` over implementing classes (`java_resolver.rs:255-259`) should be a fan-out to all implementations, each edge labelled as a possible target, or no edge plus an unresolved record.
- **Ordering a resolution ladder by anything other than confidence.** `same_dir` (0.45) before `operand` (0.70) (`call_finder.rs:94-122`) means the recorded confidence does not mean what a consumer would assume.
- **Deleting a changed file's nodes without recomputing inbound edges** (`graph_ops.rs:139-180`). Specera must query the graph for callers and inheritors of the changed set *before* deleting, and re-parse those too.
- **Matching service calls on path and verb alone.** Discarding the host (`linker.rs:403-410`) makes every third-party integration a candidate edge into your own API.
- **A parity test that logs its failures at debug level** (`testing/graphs/compare_graphs.rs:26-34`). A test that cannot fail is worse than no test, because it appears in the count.
- **Shipping an MCP tool whose purpose is to hand agent-instruction files from an indexed repository to the calling agent** (`stakgraph_rules_files`), especially alongside browser-automation tools in the same server. If Specera needs this, the content must be delivered as clearly delimited untrusted data with the injection risk stated in the tool description.

## 8. Build, borrow, buy, integrate, or reject

**Reject** — on licensing, not on merit. `FACT` There is no LICENSE file at HEAD `847d7cdc`; the sole licence in the tree covers `gateway/auth/ts` only. Default copyright reserves all rights, so StakGraph cannot be forked, vendored, embedded, or shipped as part of Specera without a written grant from Stakwork, and the deliberately-scoped MIT file for `gatekey` means the omission should not be read as an oversight awaiting a pull request. Its ideas are still the most valuable in this comparison and section 7 specifies them for independent reimplementation: the product-shaped node vocabulary, the cross-repo `Request → Endpoint` link, and in-fixture `@ast` ground-truth annotations. If Stakwork ever adds a permissive root licence, this file should be revisited — with the caveat that even then the default configuration (LSP off, four languages) resolves interface dispatch to one arbitrary implementation and loses inbound edges on every incremental sync.
