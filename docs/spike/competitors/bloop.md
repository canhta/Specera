# bloop

A Rust desktop/server application (YC S21, London) that indexed repositories into three stores at once — tantivy for lexical search, Qdrant for 384-dimension local embeddings, and a per-file tree-sitter **scope graph** serialised into the tantivy document — and drove a 4-tool ReAct agent over GPT-4 across them. **Development ceased; the repository was archived by its owner on 2025-01-02.**

## 1. Verdict

`FACT` **Dead, and archived.** HEAD is `431e9e82`, 2024-12-04, "Add 'Open with Codeanywhere' badge to README.md" — 998 commits total, **zero in the last six months and none in the ~20 months before that** apart from that badge. The GitHub API reports `"archived": true`, `"pushed_at": "2024-12-04T17:39:21Z"`, 9,506 stars (queried 2026-08-04); the repository page states "This repository was archived by the owner on Jan 2, 2025." **This corrects the coordinator brief's note that it was not archived.** `FACT` `https://bloop.ai` refuses TCP connections as of 2026-08-04.

`INFERENCE`: bloop is the **most directly relevant failure case in this spike** — it attempted precisely what Specera is considering (structural code understanding fused with an LLM agent), reached a genuinely sophisticated implementation, and stopped. The one thing it did better than anything else here is the piece nobody else attempted: **a real lexical scope graph** with typed `Def`/`Ref`/`Import`/`Scope` nodes and `RefToDef`/`RefToImport`/`DefToScope`/`ImportToScope`/`ScopeToScope` edges (`server/bleep/src/intelligence/scope_resolution.rs:54-102`), built from 13 hand-written tree-sitter `scopes.scm` query files, all Apache-2.0. What kills it is visible in the same code: `FACT` **the scope graph stops at the file boundary** ("a graph representation of scopes and names in a **single syntax tree**", `:104-105`), and cross-file "go to definition" is implemented as **string equality on symbol names** across other files' graphs (`intelligence/code_navigation.rs:332-362`). The hard part was never solved.

## 2. Core architecture and unique mechanism

`FACT` **Three coupled stores, one content-addressed cache.**
- **Lexical**: tantivy 0.21 with mmap (`server/bleep/Cargo.toml:28`). Schema in `indexes/schema.rs`: `content` and `relative_path` indexed `WithFreqsAndPositions`, plus fast fields `lang`, `avg_line_length`, `last_commit_unix_seconds`, raw byte fields for collector-level filtering, a flat `symbols` text field, and `branches`/`indexed` lists. See [zoekt](zoekt.md) for the shared trigram/lexical background.
- **Semantic**: Qdrant 1.5 (`Cargo.toml:101`). `semantic/schema.rs:16`: `EMBEDDING_DIM = 384`, cosine distance, `on_disk: true` for both vectors and payload. Payload carries `lang`, `repo_name`, `repo_ref`, `relative_path`, **`content_hash`**, `text`, `start_line`/`end_line`, `start_byte`/`end_byte`, `branches`.
- **Structural**: the serialised `ScopeGraph` is stored **inside the tantivy document** as the `symbol_locations` bytes field (`indexes/schema.rs:47`), so query-time code navigation reads graphs back out of the lexical index rather than a separate graph store.
- **Cache/metadata**: SQLite via sqlx 0.6 (`Cargo.toml:47`), table `file_cache`.

`FACT` **The embedder runs locally, two backends.** `semantic/embedder.rs`: a CPU path using ONNX Runtime through a bloop fork of `ort` (`Cargo.toml:16`, `load-dynamic`) loading `model.onnx` + `tokenizer.json` from a model directory (`:105-107`), and a GPU path loading a **ggml `q4_0` quantised** model (`apps/desktop/src-tauri/model/ggml/ggml-model-q4_0.bin`). Both are Git LFS pointers in the repo; `model.onnx` is **22,998,413 bytes** per its LFS header. `INFERENCE`: 384 dims + ~23MB ONNX places this in the MiniLM/gte-small class. **The exact model identity is `UNVERIFIED`** — the file is an LFS stub and no model card or config names it; verifiable by `git lfs pull` and reading the ONNX metadata.

`FACT` **Chunking is token-window, not AST-aware — despite tree-sitter being present.** `semantic/chunk.rs:215` `by_tokens()`: tokenize the file, pack lines until `max_tokens`, back off to the last newline, with a configurable `OverlapStrategy` (`:74-81`, either "go back N lines" or a fractional token overlap). Fallback `by_lines(src, 15)` on tokenizer failure (`:224`). A `is_noisy()` heuristic drops chunks where "over 50% of non-whitespace tokens are numeric or punctuation" (`:158-161`). `INFERENCE`: bloop had a full tree-sitter scope graph for every file and **did not use it to define chunk boundaries** — a concrete, cheap improvement it never made.

`FACT` **The scope graph.** `intelligence/scope_resolution.rs`, 1,073 lines, `petgraph::Graph<NodeKind, EdgeKind>`. `ResolutionMethod::Generic` is the only algorithm — "a basic lexical scoping algorithm" (`:30-32`) — driven by a tree-sitter `Query` per language. 13 languages ship a `scopes.scm` + `mod.rs` under `intelligence/language/`: c, c_sharp, cobol, cpp, go, java, javascript, php, python, r, ruby, rust, typescript (`scopes.scm` sizes range from 273 lines for COBOL to 463 for Rust). Grammar pins in `Cargo.toml:62-75` include BloopAI's own `tree-sitter-COBOL` fork and a `hyperpolyglot` fork for language detection (`:92`).

`FACT` **Cross-file navigation is name matching.** `intelligence/code_navigation.rs` documents its own design at `:1-3`: "scope-graph based handler that operates **only in the owning file**" and "**search based** handler that operates on any file belonging to the repo". `repo_wide_definitions()` (`:332-362`) iterates every other document's scope graph, filters to `is_top_level` nodes, and keeps those where `d.name(content) == self.active_token_text().as_bytes()`. `repo_wide_references()` (`:398-432`) does the same for `Def` and `Import` nodes. `files_importing()`/`files_imported()` (`:62-182`) build a file-level import graph by the same string comparison. There is **no import resolution, no module path handling, no type information, and no disambiguation between same-named symbols**.

`FACT` **The agent: a 4-tool ReAct loop with `MAX_STEPS = 10`** (`agent.rs:22,209`). Actions (`agent.rs:511-528`): `Code { query }` (semantic search), `Path { query }` (fuzzy path search), `Proc { query, paths }` (targeted per-file retrieval), `Answer { paths }`. The loop always fires one `code_search` on the user's stopword-stripped query before the first LLM turn (`agent.rs:183-197`). Tool selection uses OpenAI function calling, decoded by `Action::deserialize_gpt` (`:530-556`). Models (`agent/model.rs:26-53`): `gpt-3.5-turbo-finetuned` (bloop's own fine-tune, the default), `gpt-4-turbo`, `gpt-4-0613`. History is trimmed to fit via `tiktoken_rs::get_chat_completion_max_tokens` (`agent.rs:473`).

`FACT` **HyDE fallback.** `agent/tools/code.rs:15-66`: semantic search runs with `limit: 10, threshold: 0.3`; if fewer than 5 results come back, the agent generates a hypothetical document with the LLM and re-searches with **that** as the query, unioning results.

`FACT` **Scope-graph-driven context expansion.** `agent/symbol.rs:267-323` `get_related_chunks()`: for each retrieved chunk, extract hoverable symbols from the scope graph; ask the LLM to pick **one** symbol relevant to the user query (`filter_symbols`); expand that symbol into at most `MAX_CHUNKS = 3` additional chunks via its defs/refs. This is the only place the structural index feeds the LLM, and it is capped at one symbol and three chunks.

`FACT` **Answers are XML, not markdown, and are transcoded.** `agent/transcoder.rs` (1,345 lines) — "The LLM generates articles with a special format… it uses XML to denote code blocks instead of regular Markdown code blocks" (`:1-5`). The model emits `<QuotedCode><Code>…</Code><Language>…</Language><Path>…</Path><StartLine>/<EndLine></QuotedCode>` for citations and `<GeneratedCode>` for new code (`:141-162`). `decode()` sanitises malformed XML, repairs `</Code>` appearing inside code, strips comments, converts to markdown via `comrak`, and shifts 1-based model line numbers to 0-based (`:52-59`). `encode_summarized()` re-encodes an answer against a token budget (`agent.rs:310`).

`FACT` **Freshness: filesystem events for local repos, backoff polling for remotes.** `periodic/remotes.rs:21-26` — poll intervals `[60s, 3m, 10m, 20m, 30m]`; `periodic_repo_poll()` (`:130-197`) increases the interval when a repo is unchanged and resets it on change. For local repos a `notify_debouncer_mini` recursive watcher pushes change events and the poll interval is pinned to the maximum (`:210-231`), i.e. **push-triggered, poll as backstop**.

`FACT` **Incremental indexing is content-addressed, and it is the best design in this spike.** `indexes/file.rs:56-87` `cache_keys()` computes two blake3 hashes per file:
- `semantic_hash` = H(`SCHEMA_VERSION` ‖ relative path ‖ repo ref ‖ **file contents** ‖ filter-override marker);
- `tantivy_hash` = H(`semantic_hash` ‖ branch list).

`cache.rs:75-107` explains why two: "Since in Tantivy we can't update an existing record, all cache keys identify a record… universally (as in, in space & time). In QDrant, however, it is possible to update existing records, therefore the cache key is less strong." `cache.rs:217-300` `synchronize()` then reconciles: entries present in the walk are marked fresh and written to the SQLite `file_cache` table; non-fresh tantivy keys are deleted via callback; semantic hashes present in `all` but not in `fresh` are batch-deleted from Qdrant. `INFERENCE`: on a new commit only files whose content hash changed are re-tokenised and re-embedded, and because `SCHEMA_VERSION` is mixed into the hash, a schema change invalidates everything automatically with no migration code. This is strictly better than OpenGrok's `path+mtime` key ([opengrok.md](opengrok.md)) and than zoekt's shard-level rebuild ([zoekt.md](zoekt.md)).

## 3. Strongest capabilities

- `FACT` **A typed, per-file scope graph with imports as first-class nodes.** `NodeKind::{Scope, Def, Import, Ref}`, `EdgeKind::{ScopeToScope, DefToScope, ImportToScope, RefToDef, RefToImport}` (`intelligence/scope_resolution.rs:52-102`). 13 languages, each with a tested `scopes.scm`. Apache-2.0.
- `FACT` **Content-addressed incremental indexing across three heterogeneous stores** with a single reconciliation pass (`indexes/file.rs:56-87`, `cache.rs:217-300`), including automatic invalidation on schema change.
- `FACT` **Serialising the structural index into the lexical document** (`indexes/schema.rs:47`, `symbol_locations`) — one store to keep consistent instead of two, and code navigation is a tantivy read.
- `FACT` **Push-based freshness for local repos** with exponential poll backoff for remotes (`periodic/remotes.rs:21-26, 130-231`), plus `gix` (a BloopAI gitoxide fork, `Cargo.toml:98`) for in-process fetch rather than shelling out to `git`.
- `FACT` **On-device embeddings by default** — local ONNX/ggml inference (`semantic/embedder.rs`), with Qdrant bundled as a managed subprocess in the desktop app (`apps/desktop/src-tauri/src/qdrant.rs:36-142`) or as a compose service (`docker-compose.yml`). Code never leaves the machine for the retrieval half.
- `FACT` **Structured, machine-checkable citations.** The XML answer format with explicit `<Path>`/`<StartLine>`/`<EndLine>` (`agent/transcoder.rs:141-149`) makes every claim in an answer verifiable against a byte range, and the transcoder repairs malformed model output rather than discarding it.
- `FACT` **240 Rust `#[test]`/`#[tokio::test]` functions** in `server/bleep/src`, including per-language scope-resolution tests (`intelligence/language/*/mod.rs` each contain a `mod tests`) and 12 transcoder test cases. Playwright e2e specs exist under `tests/`.

## 4. Critical weaknesses

- `FACT` **Cross-file resolution is string equality.** `intelligence/code_navigation.rs:332-362, 398-432`. Two classes with a `run()` method, or a local variable shadowing an imported name, are indistinguishable. `INFERENCE`: the README's claim of "**Precise** code navigation (go-to-reference and go-to-definition) for 10+ of the most popular languages" is a `VENDOR CLAIM` that the source contradicts for anything crossing a file boundary — precision holds only within the owning file.
- `FACT` **No cross-repository or cross-service edges.** `repo_wide_*` iterates documents of one repo. Multi-repo support (`33d6a5c5`, 2024-01-30) widened *search scope*, not the graph. Dynamic wiring — DI containers, reflection, message queues, HTTP calls between services — is entirely absent from the model.
- `FACT` **Only one resolution algorithm was ever implemented.** `ResolutionMethod` has a single variant, `Generic`, and is marked `#[non_exhaustive]` (`intelligence/scope_resolution.rs:26-33`) — the extension point for language-specific resolution was declared and never used.
- `FACT` **Chunking ignores the AST** (`semantic/chunk.rs:215-333`), so embedded chunks routinely split function bodies mid-definition.
- `FACT` **Zero evaluation.** No accuracy harness, no retrieval benchmark, no golden answers anywhere in the tree. The benchmark suite that did exist was **deleted at the OSS transition**: commit `05b98068` (2024-04-03) "remove broken benches and stray dbg" removed `benches/indexes.rs`, `benches/queries.rs`, `benches/snippets.rs` and their fixtures, −2,598 lines. `INFERENCE`: the retrieval quality of the semantic+lexical+scope-graph fusion was never measured in-repo, so there is no evidence the complexity paid off.
- `FACT` **No prompt-injection defence of any kind.** Retrieved code is concatenated verbatim into the prompt (`agent/tools/proc.rs:79-85`, `agent/tools/code.rs`), and the model's function-call output is deserialised directly into an `Action` (`agent.rs:530-556`). Grepping the tree for injection/sanitisation concepts finds only `transcoder.rs:189` `sanitize()`, which repairs the model's **output** XML — it is not an input control. A malicious comment in an indexed dependency could steer tool selection.
- `FACT` **Single-user auth model.** At HEAD, `webserver/middleware.rs:12-49` has exactly two user states: `User::Unknown` and `User::Desktop { access_token, login }`. There is no tenancy, no per-path ACL, and no group model. The Cognito auth, quota, analytics, and Sentry integrations were all stripped in March 2024 (`e8a8229a`, `c410dfd7`, `40602c0c`, `49fe36bd`).
- `FACT` **Operationally heavy for what it delivers**: a Rust server, a bundled Qdrant process, a SQLite database, a tantivy index, an ONNX/ggml runtime, a Tauri desktop shell, and a React frontend — for a repository-scoped assistant.
- `FACT` **Hard-pinned to 2024 OpenAI models.** `agent/model.rs:26-67` knows only `gpt-3.5-turbo-finetuned`, `gpt-4-turbo`, `gpt-4-0613`; the last functional change (`e0d3fec2`, 2024-11-13) added gpt-4o. The default agent model is a **fine-tune bloop hosted itself**, so the default configuration cannot work at all now.
- `FACT` **Dependencies are pinned to forked git repositories** — `ort`, `esaxx-rs`, `hyperpolyglot`, `gitoxide`, `tree-sitter-cobol`, all under `github.com/bloopai` or `BloopAI` (`Cargo.toml:16,92,98,74`, workspace `Cargo.toml` `[patch.crates-io]`). `INFERENCE`: any attempt to build this today inherits unmaintained forks from an archived org.
- `FACT` **`MAX_STEPS = 10`** with no budget accounting (`agent.rs:22`), and context expansion capped at **one** LLM-selected symbol and **three** chunks (`agent/symbol.rs:268,306`).

## 6. Security, deployment, and license

`FACT` **License: Apache License 2.0** (`LICENSE:1-3`, 201 lines; GitHub API confirms `"spdx_id": "Apache-2.0"`). README: "bloop is licensed under the `Apache 2.0` license as defined in LICENSE." Permissive with an explicit patent grant — Specera may vendor, fork, modify, and ship any of this inside a closed commercial product subject only to attribution and NOTICE obligations.

`FACT` **A licensing trap exists in the git history, not at HEAD.** Commit `59a7e4a3` (2024-04-03, "remove ee features") deleted `server/bleep/src/ee/` **and its own separate `LICENSE`** — a proprietary Elastic-style term reading: "This software … may only be used in production, if you … have agreed to, and are in compliance with, the bloop Subscription Terms of Service … and otherwise have a valid bloop Enterprise license for the correct number of user seats … it is forbidden to copy, merge, publish, distribute, sublicense, and/or sell the Software." That directory contained `ee/embedder.rs` and `ee/webserver.rs`. `INFERENCE`: HEAD (`431e9e82`) is cleanly Apache-2.0, but **anything Specera copies must be taken from HEAD, never from a historical checkout or an old release tarball**, and a provenance check should confirm no `src/ee/` file was carried forward.

`FACT` **Deployment: self-hosted only, in two shapes.** A Tauri desktop app (`apps/desktop/`) that spawns Qdrant as a child process and manages its storage/snapshots/logs directories (`apps/desktop/src-tauri/src/qdrant.rs:36-162`); or a Docker Compose stack (`docker-compose.yml`) with `qdrant/qdrant` on 6333/6334 and the bleep server on 7878, taking `OPENAI_API_KEY` and `GITHUB_ACCESS_TOKEN` as build args. The Helm charts were deleted in `526145f2` (2024-04-05) — there is **no supported cluster deployment**.

`FACT` **Secrets**: a top-level `local_config.json` holding `github_access_token` and `openai_api_key` in plaintext (README, "Building From Source"); the Compose file passes the OpenAI key as a **Docker build argument**, which bakes it into image layers.

`FACT` **Egress**: OpenAI (chat + the hosted fine-tune, `llm/client.rs`), GitHub API via `octocrab` (`webserver/middleware.rs:31-37`), git fetch via the `gix` fork (`remotes.rs:135-169`), and doc scraping (`scraper/`). Embeddings are computed locally, so file contents reach OpenAI only as retrieved chunks inside prompts — not as an embedding upload.

`FACT` **Tenancy: none.** `User::Unknown | User::Desktop` (`webserver/middleware.rs:12-21`). The multi-tenant machinery (Cognito, quota, an auth bastion) was removed in March 2024.

`FACT` **Prompt-injection surface: large and undefended.** Indexed code — including third-party dependencies — flows verbatim into the system prompt as tool results, and the model's function call is deserialised straight into a tool invocation (`agent.rs:530-556`). No provenance marking, no instruction-content separation, no allowlist on tool arguments. `INFERENCE`: this is the exact surface Specera inherits the moment it puts a model on top of retrieval, and bloop is the reference for how *not* to leave it open.

## 7. Ideas to adopt or avoid

### Adopt

- **Content-addressed cache keys with the schema version baked in** (`indexes/file.rs:56-87`): `blake3(SCHEMA_VERSION ‖ path ‖ repo ‖ contents ‖ filter_state)`. Specera should key **every** derived artifact this way. It gives correct incremental updates for free, makes schema migration a no-op (bump the version, everything re-derives), and — unlike OpenGrok's mtime key — cannot be fooled by a fresh clone or a touched file.
- **Two cache keys for two store semantics** (`cache.rs:75-107`): a strong key for append-only stores that cannot update in place, a weaker content-only key for stores that can upsert. Specera will have exactly this mix (an immutable lexical index plus a mutable vector store), and this is the right way to express it.
- **The reconcile-and-sweep pass** (`cache.rs:217-300`): after a walk, everything not marked fresh is deleted from every store in one transaction. Specera should copy this shape rather than trying to compute deletions from a diff.
- **Store the structural index inside the lexical document** (`indexes/schema.rs:47`, `symbol_locations`). One store, one commit, no cross-store consistency problem for the graph. Specera should keep its symbol/scope data co-located with the text it annotates.
- **The `NodeKind`/`EdgeKind` vocabulary** (`intelligence/scope_resolution.rs:52-102`) — `Scope`/`Def`/`Import`/`Ref` with `RefToDef`, `RefToImport`, `DefToScope`, `ImportToScope`, `ScopeToScope`. Modelling **imports as their own node type** with their own edge kind is the correct primitive for later adding real cross-file resolution: an unresolved `Import` node is exactly where the resolver plugs in. Specera should adopt this shape and then do the thing bloop did not — resolve `Import` nodes to concrete targets using module/build metadata instead of name equality.
- **The 13 `scopes.scm` files themselves** (`intelligence/language/*/scopes.scm`, 273–463 lines each, Apache-2.0). These are months of hand-tuned tree-sitter query work Specera can lift directly for c, c#, cobol, cpp, go, java, javascript, php, python, r, ruby, rust, typescript. This is the single most valuable extractable asset in the repository.
- **XML-with-explicit-line-ranges as the answer format, plus a repairing transcoder** (`agent/transcoder.rs:141-162`, `decode()` at `:19-50`). Forcing the model to emit `<Path>`/`<StartLine>`/`<EndLine>` makes every citation mechanically verifiable against the index; the transcoder's willingness to repair malformed XML rather than fail is what makes it survive real model output. Specera should require this for any generated claim about code and **reject any citation whose byte range does not match the indexed content** — a check bloop specified the format for but never enforced.
- **Push-plus-backoff freshness** (`periodic/remotes.rs:21-26, 210-231`): filesystem notifications where available, exponentially backing-off polling where not, interval reset on change.
- **HyDE only as a fallback below a result-count threshold** (`agent/tools/code.rs:42-66`) — pay for the extra LLM call only when retrieval visibly underperformed, not on every query.

### Avoid

- **Name-equality as cross-file resolution** (`intelligence/code_navigation.rs:332-362`). This is the specific shortcut that made bloop's "precise code navigation" claim false, and it is the exact gap Specera must fill to differentiate. Do not ship it as a placeholder — it produces confidently wrong navigation, which is worse than none.
- **Building a tree-sitter parse of every file and then chunking by token windows anyway** (`semantic/chunk.rs:215-333`). If the AST is already there, chunk on its boundaries.
- **Deleting the benchmark suite** (`05b98068`, −2,598 lines) — bloop ended with a three-store retrieval pipeline whose quality was, by its own repository's evidence, entirely unmeasured.
- **Shipping a hosted fine-tune as the default model** (`agent/model.rs:26-27`, `gpt-3.5-turbo-finetuned`). It makes the default configuration inoperable the moment the vendor stops hosting it — which is what happened.
- **Depending on your own forks of upstream crates** (`ort`, `esaxx-rs`, `hyperpolyglot`, `gitoxide`, `tree-sitter-cobol`). Five forks became five orphans on the day the org archived.
- **Passing an API key as a Docker build arg** (`docker-compose.yml`) — it persists in image layers.
- **Concatenating retrieved code into a prompt with no provenance boundary** (`agent/tools/proc.rs:79-85`, `agent.rs:530-556`).

### The post-mortem itself

`FACT` **What the final state actually was.** Between 2024-03-27 and 2024-04-05 the repository was systematically stripped of commercial infrastructure in a single burst: `40602c0c` remove analytics, `49fe36bd` remove sentry, `c410dfd7` remove quota, `cf233a86` "roll llm api into bloop", `e8a8229a` "wip: remove cognito auth", `59a7e4a3` remove ee features (+ the EE licence), `05b98068` remove broken benches, `b7d0ec9a` "OSS FE", `526145f2` remove helm charts and the qdrant config. The README was edited in the same window to delete the line "it is currently _not_ possible to use conversational GPT-4 search where bloop has been built from source" and replace it with bring-your-own-OpenAI-key instructions (`526145f2`, README diff). `INFERENCE`: this is the signature of a company **withdrawing a hosted commercial product and leaving a self-hostable OSS build behind**, not of ordinary refactoring. After 2024-04-23 (`v0.6.5`) only five commits landed, all cosmetic: a Chinese locale file, a docs-link fix, a Docker apt-cache cleanup, a gpt-4o bump, and the README badge at HEAD.

`INFERENCE` **Why it likely stopped — anchored, not asserted.** The repository shows a COBOL push immediately before the wind-down: `c712a3f7` (2024-01-12) "add scope-queries for cobol", reverted twice then re-landed, `700ff3d1` (2024-02-08) "add code coloring for cobol", a 273-line `intelligence/language/cobol/scopes.scm`, and a dependency on BloopAI's **own** `tree-sitter-COBOL` fork (`Cargo.toml:74`) — COBOL is not a plausible priority for a general developer code-search tool. `VENDOR CLAIM`/external corroboration: bloop.ai now describes itself as a legacy-modernisation lab converting COBOL to Java, and published *COBOLEval*, a COBOL adaptation of HumanEval, plus "mAInframer-1" fine-tunes (`https://bloop.ai/blog/evaluating-llms-on-cobol`). Taken together: **bloop appears to have pivoted from horizontal AI code search to vertical COBOL→Java mainframe modernisation, and archived the code-search product.** `UNVERIFIED`: no statement of reasons exists in the repository, in `CONTRIBUTING.md`, or in any README banner — grepping all markdown for "sunset", "deprecated", "no longer maintain", "archived", "discontinued" returns nothing. Confirmation would require a public post-mortem from BloopAI or the founders, which was not found.

`INFERENCE` **The lesson for Specera, stated plainly.** bloop was not killed by bad engineering — the incremental cache is the best in this spike and the scope graph is the only real one. It shipped a semantic-search-plus-LLM-agent product with (a) cross-file resolution that was string matching, (b) chunking that ignored the AST it had already computed, and (c) **no measurement of whether any of it retrieved the right code**. A general "chat with your codebase" product built on those three properties did not sustain a business against general coding assistants. If Specera's differentiation is semantic code understanding, the differentiation has to be the part bloop skipped — real resolution across files, repos, and services, with a retrieval-quality benchmark attached.
