# Aider

A terminal-based pair-programming agent: user adds files to a chat, aider sends them plus a PageRank-ranked tree-sitter "repo map" to an LLM, parses the reply into file edits, applies them, and git-commits each change.

## 1. Verdict

Component and reference implementation, not a competitor. Aider covers exactly one Specera lane — implementation — and does it with more measured rigour than anything else in this spike: it is the only repo here that ships a reproducible benchmark harness plus 69 recorded runs of it, so its claims about which edit format works are numbers, not assertions. The single thing it does better than anything else is **making an LLM's edits mechanically applicable and reversible**: a ranked repo map under a hard token budget (`aider/repomap.py:629`), four fallback edit formats with recorded well-formedness rates, and one git commit per LLM change with authorship attribution (`aider/repo.py:131`). What kills it as a competitor is scope and posture: it is a single-user interactive CLI over one local git repo, with no requirements, no ticket, no PR, no test-generation, no security, no release, no server; and it is decelerating hard — 1292 commits in 2025-03 versus 5 in 2026-05 (`git log --date=format:'%Y-%m'`). It also does zero secret redaction before sending file contents to a model.

## 2. Core architecture and unique mechanism

**Repo map = tree-sitter tags + personalized PageRank over a name-identity graph.** `FACT`

1. **Tag extraction** (`aider/repomap.py:279-363`). For each file, `filename_to_lang()` (from `grep-ast`) picks a language; a `.scm` tags query is loaded from `aider/queries/tree-sitter-language-pack/<lang>-tags.scm` (32 files: arduino, bash, c, chatito, clojure, commonlisp, cpp, csharp, d, dart, elisp, elixir, elm, gleam, go, java, javascript, lua, matlab, ocaml, ocaml_interface, pony, properties, python, r, racket, ruby, rust, solidity, swift, udev) with a 28-file `tree-sitter-languages` fallback dir. Captures named `name.definition.*` become `kind="def"`, `name.reference.*` become `kind="ref"` (`repomap.py:319-324`). Each tag is `(rel_fname, fname, line, name, kind)` — **an identifier string and a line number, nothing else. No type, no scope, no signature, no arity.** `FACT`
2. **Reference backfill via lexer.** If a language's query file yields defs but no refs (the comment names C++), aider falls back to pygments `guess_lexer_for_filename` and emits every `Token.Name` in the file as a `ref` with `line=-1` (`repomap.py:338-363`). `FACT` — this is a bag-of-identifiers approximation, not parsing.
3. **Graph construction** (`repomap.py:470-514`). A `networkx.MultiDiGraph`; nodes are relative file paths; an edge `referencer -> definer` is added for every identifier that is both defined somewhere and referenced somewhere. **Edges are pure string identity on the identifier name — no import resolution, no symbol table, no type inference.** Edge weight:
   - `mul = 1.0`; `×10` if the identifier was mentioned in the user's message; `×10` if it is snake/kebab/camelCase **and** ≥8 characters; `×0.1` if it starts with `_`; `×0.1` if the identifier is defined in more than 5 files (`repomap.py:487-499`)
   - `×50` if the referencing file is currently in the chat (`repomap.py:508-509`)
   - `× sqrt(num_refs)` to damp high-frequency names (`repomap.py:512`)
4. **Ranking** (`repomap.py:519-545`). `nx.pagerank(G, weight="weight", personalization=..., dangling=...)`. Personalization vector = `100/len(fnames)` assigned to files in the chat, files named in the user's message, and files whose path components match a mentioned identifier (`repomap.py:383, 422-445`). Then the rank of each file is **redistributed across its outgoing edges proportional to weight**, so the final ranked unit is a `(defining_file, identifier)` pair, not a file (`repomap.py:534-545`). This is the "which definitions matter to the code that would call them" step and is the actually novel bit.
5. **Budget fitting** (`repomap.py:666-706`). Binary search over how many ranked tags to include: render the tag list to a tree, count tokens, halve/double until within 15% of `max_map_tokens` or under it. Starting midpoint `min(max_map_tokens // 25, num_tags)`. Token counting itself is **sampled and extrapolated** for text ≥200 chars — every 100th line is tokenized and scaled by character ratio (`repomap.py:89-101`). `FACT` — the budget is therefore approximate by construction.
6. **Rendering** (`repomap.py:710-784`). `grep_ast.TreeContext` prints only the lines of interest plus enclosing scope headers; every output line is hard-truncated to 100 chars (`repomap.py:782`).
7. **Budget policy** (`repomap.py:120-132`, `aider/models.py:782-789`). Default map budget is `clamp(max_input_tokens/8, 1024, 4096)`. With **no** files in the chat the budget is multiplied by `map_mul_no_files=8` (capped at `context_window - 4096`) — deliberately spend more on orientation when you have no anchor.

**Caching / freshness.** Tags are cached per file in a `diskcache`/SQLite store at `.aider.tags.cache.v4`, keyed by absolute filename with the file's `mtime` stored alongside; a mismatch triggers re-parse of that file only (`repomap.py:233-264`). `FACT` The rendered map is cached in-process by `(chat_files, other_files, max_tokens, mentioned_fnames, mentioned_idents)`; refresh policy is `auto` (reuse if the last build took >1.0s), `always`, `files`, or `manual` (`repomap.py:592-614`). `FACT`

**Edit application.** Five real formats, each a `Coder` subclass (`aider/coders/__init__.py`): `whole` (`wholefile_coder.py`), `diff` = SEARCH/REPLACE blocks (`editblock_coder.py`, 657 lines, plus a 757-line fuzzy matcher `search_replace.py`), `diff-fenced`, `udiff` (`udiff_coder.py`, 429 lines), `patch` (`patch_coder.py`, 706 lines), plus `architect`, `ask`, `context`, `help` as non-editing modes.

**Architect mode** (`aider/coders/architect_coder.py`) is a two-model split: a reasoning model produces prose describing the change with `map_tokens=0` disabled for the editor; its output is then fed verbatim as the user message to a second `Coder` instance (`editor_model`, `editor_edit_format`) whose only job is to emit well-formed edits. `FACT`

**Self-repair loop** (`aider/coders/base_coder.py:1585-1623`, `:933-944`). After applying edits: auto-commit → if `auto_lint` (default **True**), run linter on edited files, commit the lint run separately, and on errors set `reflected_message = lint_errors` → if `auto_test` (default **False**) run `test_cmd`, on failure set `reflected_message = test_errors`. A malformed edit response also sets `reflected_message` (`:2315`, `:2327`). The reflected message is re-sent as the next user turn, capped at `max_reflections = 3` (`:100-101`, `:939-940`). `FACT` The linter is tree-sitter-aware: for Python it lints with a built-in `py_lint`, and errors are mapped back to line numbers and re-rendered as `TreeContext` snippets (`aider/linter.py:21-27, 68-80`).

**Git discipline** (`aider/repo.py:131-250`). Every applied edit set is committed by `auto_commit()` (`base_coder.py:1589`), with an LLM-generated commit message built from the chat context, and configurable attribution: `attribute_author`, `attribute_committer`, `attribute_commit_message_author`, `attribute_commit_message_committer`, `attribute_co_authored_by` — the last emits a `Co-authored-by: aider (<model>) <aider@aider.chat>` trailer (`repo.py:69-88, 168`). Dirty working-tree changes are committed *before* edits (`dirty_commit()`, `base_coder.py:2291`) so the AI change is isolated in its own commit and `/undo` is a clean revert. `FACT`

**Chat assembly** (`aider/coders/chat_chunks.py`). Messages are ordered `system + examples + readonly_files + repo(map) + done(history) + chat_files + cur + reminder`, and prompt-cache breakpoints are placed at the examples/system boundary, after the repo-map chunk, and after chat files (`chat_chunks.py:17-54`) — i.e. the ordering exists so the expensive, slow-changing repo map sits inside the cacheable prefix. `FACT` Chat history over budget is summarized recursively by a separate model call (`aider/history.py:32-70`).

## 3. Strongest capabilities

- **A real, reproducible benchmark harness in-repo.** `benchmark/benchmark.py` (1059 lines) runs 225 Exercism "polyglot" exercises inside a Docker container (`benchmark/Dockerfile`, `docker_build.sh`), each with `--tries` (default 2) attempts where attempt 2 receives the failing test output (`benchmark.py:200, 847-892`). It records not just pass rate but `percent_cases_well_formed`, `num_malformed_responses`, `lazy_comments`, `syntax_errors`, `indentation_errors`, `exhausted_context_windows`, `test_timeouts`, `seconds_per_case`, `total_cost` (`aider/website/_data/polyglot_leaderboard.yml`). `FACT`
- **Edit-format quality is measured, not asserted.** 69 recorded polyglot runs and 98 in the older `edit_leaderboard.yml`, each pinned to the aider `commit_hash` it was run at. Across polyglot runs `percent_cases_well_formed` ranges from **64.4% to 100%** — i.e. the format-compliance failure mode is real and quantified. `FACT`
- **Architect mode's benefit is quantified.** `o3 (high) + gpt-4.1` in architect mode: `pass_rate_2: 78.2`, 100% well-formed, `seconds_per_case: 137.4` (`polyglot_leaderboard.yml`). `DeepSeek R1 + claude-3-5-sonnet` architect: `pass_rate_2: 64.0`, 100% well-formed. In the older 133-case suite, `claude-3.5-sonnet` architect scored `pass_rate_2: 80.5` vs `77.4` for the same model in plain `diff` mode, both at 100%/99.2% well-formed (`aider/website/_data/architect.yml`). `FACT` — architect mode buys well-formedness reliably and pass rate marginally, at a large latency cost.
- **Graceful degradation everywhere in the map path.** SQLite cache corruption falls back to recreating the cache then to an in-memory dict (`repomap.py:177-222`); `RecursionError` on huge repos disables the map rather than crashing (`repomap.py:143-146`); `ZeroDivisionError` in PageRank retries without personalization then returns `[]` (`repomap.py:526-531`). `FACT`
- **`ContextCoder` — an LLM-driven file-selection pass.** A dedicated mode whose only job is to name the files needed for a request; it forces `refresh="always"`, multiplies the map budget by 8, then iterates until the model's file list stabilises (`aider/coders/context_coder.py:14-46`). `FACT`
- **Substantial test suite for the core.** 926 test functions / 12,381 lines under `tests/`, including `tests/basic/test_repomap.py` (510 lines), `test_editblock.py` (618), `test_wholefile.py` (359), `test_udiff.py` (119), `test_coder.py` (1438), plus language fixtures under `tests/fixtures/languages` and a golden `sample-code-base-repo-map.txt`. `FACT`
- **Apache-2.0**, permissive for borrowing. `FACT` (`LICENSE.txt:1-3`)

## 4. Critical weaknesses

- **No secret redaction whatsoever.** File contents in the chat are sent verbatim to the model provider. `grep -ril "redact\|secretlint\|credential" aider/ --include=*.py` returns only unrelated hits (`models.py`, `analytics.py`, `exceptions.py`, prompt files) — there is no scanner, no masking, no allowlist. `FACT` For Specera this is disqualifying as-is.
- **Graph edges are string-identity, not resolved references.** `defines[name]` / `references[name]` are keyed on the bare identifier text (`repomap.py:451-458`). Two unrelated `run()` methods in different modules produce a real edge. The only mitigation is the heuristic `if len(defines[ident]) > 5: mul *= 0.1` (`repomap.py:498-499`) — a popularity penalty, not disambiguation. `FACT`
- **Dynamic and cross-service dependencies are invisible.** DI containers, reflection, config-driven wiring, message-queue topics, and HTTP calls between services produce no edges unless the literal identifier happens to appear as a lexer `Name` token in both files. There is no import graph, no route table, no config parsing anywhere in `repomap.py`. `FACT`
- **The graph is fully rebuilt on every map refresh.** `get_ranked_tags()` iterates all files, rebuilds the `MultiDiGraph` from scratch, and re-runs PageRank over the whole repo (`repomap.py:365-574`). Only *tag extraction* is incremental (mtime-keyed). On a one-line commit the entire PageRank is recomputed. `FACT`
- **Hard single-repo boundary.** `self.root` is one directory; `get_rel_fname` is relative to it (`repomap.py:63-65, 169-175`); the file set is the git repo's files. A polyrepo system has no representation. `FACT`
- **Token budget is estimated, not exact.** Sampled every-100th-line extrapolation (`repomap.py:89-101`) plus a 15% acceptance band in the binary search (`repomap.py:689-691`). `FACT` Combined with `exhausted_context_windows` appearing as a tracked benchmark failure mode, this is a known live failure class.
- **Line truncation at 100 chars destroys long lines** in the map output (`repomap.py:782`) — minified files, long signatures, and long string literals are silently cut. `FACT`
- **Autonomy is shallow.** `max_reflections = 3` (`base_coder.py:101`); `auto_test` defaults to **False** (`:106`); after lint or test failure it asks the human `confirm_ask("Attempt to fix ... errors?")` before retrying (`:1604, :1620`). This is a supervised loop, not an autonomous one. `FACT`
- **The benchmark measures the wrong unit for Specera.** Exercism exercises are self-contained single-file katas with pre-written tests; they test edit-format compliance and single-function coding, **not** cross-file navigation, not repo comprehension, not whether the repo map found the right files. There is no repo-map accuracy benchmark in the repo. `FACT` The `refactor_leaderboard.yml` / `benchmark/refactor_tools.py` suite (Python `ast`-based, 209 lines) is the closest thing to a multi-file test and covers Python only.
- **Project is decelerating sharply.** 78 commits in the last 6 months against 13,138 total; monthly counts fell from 1292 (2025-03) to 5 (2026-05); HEAD is `5dc9490bb` dated 2026-05-22, ~2.5 months stale at time of reading. `FACT`
- **Opt-in telemetry to a third party.** `aider/analytics.py:9,56-57` ships a hard-coded PostHog project key and US host; enabled only after an explicit opt-in prompt offered to 10% of users (`PERCENT = 10`, `:15, :119-135`). `FACT` — opt-in and disableable, but it is outbound egress in a coding tool.

## 6. Security, deployment, and license

- **Deployment**: a `pip`-installed local CLI (`pyproject.toml: name = "aider-chat"`, `requires-python = ">=3.10,<3.15"`, version `0.86.3.dev`). No server, no tenancy model, no auth — it runs as the invoking user with full write access to the git worktree. A `docker/` dir exists for containerized use.
- **Secrets**: user supplies provider API keys via env/config. **No redaction of repo content before transmission** (§4). Every file the user `/add`s, plus the repo map covering the whole repo, goes to the configured model endpoint.
- **Network egress**: model provider (via `litellm`), PostHog telemetry when opted in (`aider/analytics.py:56-57`), model-metadata fetches (`aider/models.py`, `aider/openrouter.py`), and `aider/scrape.py` for URLs pasted into chat (fetches arbitrary user-supplied web pages into the prompt).
- **Prompt-injection surface**: real and unmitigated. Repo file contents, linter output, test output (`base_coder.py:1600, 1617`), scraped web pages (`aider/scrape.py`), and shell command output (`run_shell_commands`, `base_coder.py:1609`) are all concatenated into the next model turn. A malicious source file or a crafted test failure message can steer the next edit. There is no sanitisation or trust boundary between repo content and instructions. `FACT`
- **Shell execution**: `aider/coders/shell.py` and `run_shell_commands` let the model propose shell commands; gated by a confirm prompt, but `--yes` exists (`aider/args.py`).
- **License**: Apache License 2.0, `/home/ubuntu/projects/Specera/.spike/clones/aider/LICENSE.txt:1-3` (note: file is `LICENSE.txt`, not `LICENSE`). `FACT` Permissive with an explicit patent grant — the repo-map algorithm and edit-format parsers can be copied into Specera with attribution and a NOTICE-style acknowledgement. The `.scm` tag query files under `aider/queries/` are derived from tree-sitter grammar repos and carry their own upstream licenses (see `aider/queries/tree-sitter-language-pack/README.md`) — check those individually before vendoring. `INFERENCE` from the presence of that README and the standard provenance of `-tags.scm` files.

## 7. Ideas to adopt or avoid

### Adopt

- **The personalized-PageRank-then-redistribute-over-out-edges ranking** (`repomap.py:519-545`). Specera should implement this over a *resolved* symbol graph rather than a name-identity graph: same algorithm, better edges. The personalization vector keyed on "files the user is touching + identifiers in the user's message" is the mechanism that makes the map task-relative instead of static, and it is cheap.
- **Binary search to a token budget with an explicit error band** (`repomap.py:666-706`). Specera's context packer should do exactly this: render candidate context at N items, count, bisect, accept within a stated tolerance. Do the token count *exactly* rather than by sampling.
- **The `map_mul_no_files = 8` policy** (`repomap.py:124-132`): when there is no anchor file, spend ~8× the budget on breadth. Specera should generalise this to "budget is a function of how well-specified the task is."
- **Per-file mtime-keyed tag cache with a `CACHE_VERSION` in the directory name** (`repomap.py:35-43, 233-264`). Bumping the version renames the cache dir, so an extractor change invalidates everything with zero migration code. Specera should copy this exact trick for its index.
- **Commit-per-AI-change with machine-readable attribution** (`repo.py:69-88, 168`; `base_coder.py:1589`). Committing the dirty tree first so the AI change is isolated is the detail that makes rollback trustworthy. Specera should make this mandatory and non-optional, and use the `Co-authored-by` trailer so provenance survives into `git log` and PR review.
- **Lint/test failure as a structured reflection message with a hard iteration cap** (`base_coder.py:1596-1623`, `max_reflections = 3`). Adopt the cap. Unbounded self-repair loops burn money and diverge.
- **The benchmark harness's *metrics*, not its exercises.** Recording `percent_cases_well_formed`, `num_malformed_responses`, `exhausted_context_windows`, `seconds_per_case`, `total_cost` per run, pinned to the tool's own commit hash (`polyglot_leaderboard.yml`) is the right shape for Specera's eval. Specera's exercises should be repo-comprehension and cross-file-change tasks, but the result schema can be lifted directly.
- **Architect/editor split with `map_tokens=0` on the editor** (`architect_coder.py:26-31`). Separating "decide the change" from "emit syntactically valid edits" measurably fixes well-formedness. Specera should use it for its implementation stage and give the editor model no repo map at all.
- **Prompt-cache breakpoint placement tied to change frequency** (`chat_chunks.py:17-54`). Order context blocks by volatility and set cache breakpoints at the boundaries. This is a pure cost win.

### Avoid

- **Name-identity graph edges.** The `×0.1`-if-defined-in->5-files hack is an admission that the edges are wrong. Specera needs import/type resolution.
- **Sampled token estimation** (`repomap.py:89-101`). Cheap, but it is why `exhausted_context_windows` is a tracked failure mode.
- **Truncating map lines to 100 chars** (`repomap.py:782`). Silent lossy truncation with no marker.
- **Pygments `Token.Name` reference backfill** (`repomap.py:347-363`). Emitting every identifier token in a file as a "reference" with `line=-1` is noise that then gets PageRanked.
- **`auto_test` defaulting to False and gating retries behind a human confirm** (`base_coder.py:106, 1604, 1620`). For an autonomous SDLC platform the default must be inverted.
- **Benchmarking on self-contained katas.** It measures edit formatting, not repo comprehension — the thing Specera has to be good at.
- **Shipping a hard-coded third-party telemetry key in the binary** (`analytics.py:56-57`). Enterprise buyers will fail this on review regardless of opt-in.

## 8. Build, borrow, buy, integrate, or reject

**Borrow.** Apache-2.0 (`LICENSE.txt`) permits lifting the ranking algorithm, the budget-fitting binary search, the mtime+CACHE_VERSION cache design, the edit-format parsers (`editblock_coder.py` + `search_replace.py` encode years of hard-won LLM-output-repair heuristics — 1414 lines Specera should not re-derive), and the benchmark result schema, with attribution. Do **not** integrate aider as a runtime dependency: it is a single-user interactive CLI with no server or tenancy model, no secret redaction, and a project cadence that fell from 1292 commits/month to 5. Treat the repo as a design document with running code attached, and re-implement the graph layer on resolved references rather than string identity.
