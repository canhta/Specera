# CodeGraphContext (CodeGraphContext/CodeGraphContext, OSS CLI + MCP)

A Python CLI/MCP server that tree-sitter-parses 24 language modules into a **property graph** (27 node labels, 27 relationship types) written over one of **six pluggable graph backends** (FalkorDB Lite, KùzuDB, LadybugDB, FalkorDB remote, Neo4j, Nornic), resolving calls through a 9-tier heuristic ladder whose confidence tier is persisted on every edge — and optionally through external SCIP compiler indexers instead.

## 1. Verdict

`FACT` CodeGraphContext (CGC) is the only repo in this set that both **persists resolution confidence on the edge** (`confidence`, `resolution_tier`, `confidence_label` set on every CALLS write — `src/codegraphcontext/tools/indexing/persistence/writer.py:856-858`) and **splits the relationship type by confidence** (`HEURISTIC_CALLS` when tier ≥ 8, `CALLS` otherwise — `writer.py:741-746`). `FACT` It is also the only one with a compiler-accurate escape hatch: `SCIP_INDEXER=true` swaps tree-sitter heuristics for Sourcegraph SCIP indexers (Pyright, tsc, scip-go, scip-java, scip-clang, scip-dotnet) driving the same Cypher writers (`src/codegraphcontext/tools/scip_indexer.py:1-36`). `FACT` What kills it as a component: **nothing in the query layer ever reads the confidence it so carefully stores** — `grep -rn "min_confidence\|confidence_threshold\|confidence >" src/` returns zero hits, and all 14 traversal queries in `code_finder.py` match `[:CALLS|HEURISTIC_CALLS]`, so a 0.08-confidence "I gave up and pointed at the caller's own file" edge is walked identically to a 1.00-confidence `this.foo()` edge. `FACT` Its own in-repo audit admits the accuracy numbers are circular: `CGC_GRAPH_INCONSISTENCIES.md` item 78 — "Circular perfection gate (export vs itself) | Indexer vs source truth | Misleading 21/21 PASS" — and item 79 — "CALLS avg 84.6% vs perfection 100% | Single metric | Conflicting reports". `FACT` MIT-licensed, so everything here is legally borrowable.

## 2. Core architecture and unique mechanism

**Pipeline.** `FACT` `cgc index` → `GraphBuilder.build_graph_from_path_async` (`src/codegraphcontext/tools/graph_builder.py:1158`) → per-file tree-sitter parse → `pre_scan_for_imports` builds a repo-wide `imports_map: {symbol → [paths]}` → `GraphWriter` MERGEs nodes → `build_function_call_groups` (`resolution/calls.py`) resolves calls → `build_inheritance_and_csharp_files` (`resolution/inheritance.py`) → optional Phase 4/5 (`embeddings.py`, `post_resolution.py`).

**The schema is declared in one file** — `src/codegraphcontext/tools/indexing/schema_contract.py` (77 lines), described in-source as "documentation + test hooks only".

`FACT` **27 node labels** (`schema_contract.py:11-35`):
`Repository, Directory, File, Function, Class, Trait, Variable, Interface, Macro, Struct, Enum, EnumMember, Union, Record, Property, Annotation, Module, Parameter, MavenModule, GradleModule, ExternalLibrary, Datasource, DbTable, DbColumn, RedisKeyPattern`.

`FACT` **27 relationship types** (`schema_contract.py:38-67`):
`CONTAINS, CALLS, HEURISTIC_CALLS, IMPORTS, INHERITS, HAS_PARAMETER, INCLUDES, IMPLEMENTS, PARTIAL_OF, PART_OF, DECORATED_BY, METACLASS, COMPANION_OF, EMBEDS, INJECTS, EXPOSES_ENDPOINT, PROVIDES_BEAN, MODULE_DEPENDS_ON, USES_LIBRARY, CHILD_MODULE, FILE_BELONGS_TO, READS, WRITES, MAPS_TO, HAS_COLUMN, STORED_IN`.

`FACT` Merge keys are coordinate-based, not qualified-name-based: `FUNCTION_MERGE_KEYS = ("name", "path", "line_number")`, same for `Class`; `File`/`Repository`/`Directory` merge on `path` alone (`schema_contract.py:70-76`). `INFERENCE` Identity therefore moves whenever a function shifts a line, which is why the incremental path deletes-and-rebuilds rather than diffing node properties.

`FACT` Three declared relationship types are **never written anywhere**: `EXPOSES_ENDPOINT`, `PROVIDES_BEAN`, and `FILE_BELONGS_TO` appear only in `schema_contract.py` (`grep -rl` over `src/` returns that one file each). `FACT` The published graph-model doc (`docs/docs/concepts/graph-model.md`) documents `SpringBean` and `SpringEndpoint` node labels that exist in **neither** `NODE_LABELS` nor anywhere in `src/`.

**Parser strategy — tree-sitter by default, SCIP by opt-in.**
- `FACT` Default path: `tree-sitter` + `tree-sitter-language-pack>=1.6,<2.0` (`README.md:316`), loaded lazily and cached per-language because "parsers are NOT thread-safe" (`src/codegraphcontext/utils/tree_sitter_manager.py:1-13`). 31 modules in `tools/languages/`, of which 24 declare a `language_name`.
- `FACT` Optional path: `SCIP_INDEXER=true` (default `"false"`, `src/codegraphcontext/cli/config_manager.py:112`) shells out to the language's real type-checker via Sourcegraph's SCIP CLIs — `scip-python` (Pyright), `scip-typescript` (tsc), `scip-go`, `scip-rust`, `scip-java` (also Kotlin/Scala), `scip-clang`, `scip-dotnet`, `scip_dart` — parses `index.scip` protobuf (`tools/scip_pb2.py`, 2456 lines of generated protobuf) and writes through the same Cypher MERGEs, then runs a tree-sitter supplement pass for complexity/source/decorators (`scip_indexer.py:17-21`). `INFERENCE` This is the single most important architectural idea in the repo: one graph schema, two extraction fidelities, chosen per repo. `FACT` It is off by default and requires the user to install each external toolchain (and, for C/C++, produce `compile_commands.json` — `README.md:288`).
- `FACT` Language claim inflation: `README.md:173` says "Full support for 23 programming languages" and the table lists CSS, HTML and TSX among them. `css.py` (93 lines) emits CSS **selectors as `Function` nodes** — `"functions": [{"name": s["name"], ...}]` where names are `.class`, `#id`, or a bare tag name like `form` (`tools/languages/css.py:79-89`). `INFERENCE` Because `languages_are_compatible()` returns `True` whenever either side's language is unknown and `.css` is absent from `_SUFFIX_TO_LANG` (`resolution/calls.py:56-100`), a bare-tag CSS "function" is an eligible name-match target for a real call in another language.

**Call resolution — a 9-tier ladder with explicit confidences** (`resolution/calls.py:30-52`):

| Tier | Conf | Rule |
|---|---|---|
| 1 | 1.00 | explicit `this`/`self`/`super` receiver |
| 2 | 0.95 | local function/class in the same file |
| 3 | 0.88 | inferred receiver type + FQN import key |
| 4 | 0.72 | inferred receiver type + short-name/type fallback |
| 5 | 0.90 | unique short name or same-package lookup |
| 6 | 0.85 | qualified/wildcard import lookup |
| 7 | 0.70 | FQN path-substring match |
| 8 | 0.25 | **alphabetical-first of multiple candidates** |
| 9 | 0.08 | **same-file fallback for unresolved `obj.method()`** |

`FACT` Tier 8 is literally `resolved_path = candidates[0]` after all import heuristics fail (`calls.py:1546-1547`); tier 9 is `resolved_path = caller_file_path` (`calls.py:1550`). `FACT` Both map to `confidence_label = "AMBIGUOUS"` (`calls.py:44-51`) and to the `HEURISTIC_CALLS` relationship type. `FACT` The write is `MATCH (called:{label} {name, path})` (`writer.py:864`), so a tier-9 edge only materialises if a same-named node happens to exist in the caller's own file — no phantom nodes, but a wrong-target edge when the name collides locally.

**Interfaces, inheritance and DI.**
- `FACT` `INHERITS`/`IMPLEMENTS` resolution is name + import-path-substring matching: `if full_import_name.replace(".", "/") in path` (`resolution/inheritance.py:37-55`), falling back to `possible_paths[0]` only when there is exactly one candidate. No MRO, no linearisation.
- `FACT` Interface-dispatch repair exists but is **off by default**: `post_resolution.py` re-resolves tier-8/9 edges by walking the `INHERITS` graph and bumping them to `resolution_tier=10` (`post_resolution.py:2-13`), gated on `ENABLE_INHERIT_RESOLVE` (default `"false"`, `config_manager.py:126`).
- `FACT` Dependency injection has a real edge (`INJECTS`, "#887 Spring DI semantic edges") written for Java/Spring and queried by `java_toolkit.py:239` and `analysis_handlers.py` — the only DI-aware graph in this comparison set.
- `FACT` There is **no dynamic-dispatch synthesis at all** — no callback, event-emitter, reflection, message-queue, or config-wiring resolver anywhere in `src/`.
- `FACT` A third resolution tier is embedding-based: `ENABLE_VECTOR_RESOLVE` (default `"false"`) embeds each `Function`'s qualified name + docstring + params (`indexing/embeddings.py:67-80`) and picks call targets by cosine similarity, documented as "a tiebreaker for Phase 5, not a replacement" (`config_manager.py:183-192`). `INFERENCE` Resolving a call edge by docstring similarity is a false-edge generator; that it is off by default and documented as a tiebreaker is the right call, but the edge it produces is indistinguishable in the graph from a tier-7 static match apart from its tier number, which nothing reads.

**Storage — six backends behind one Cypher-ish interface.** `FACT` `core/database.py` (Neo4j, bolt), `database_nornic.py` (Neo4j-wire-compatible), `database_falkordb.py` (FalkorDB Lite, in-process, **default on Unix** — `README.md` Database Options), `database_falkordb_remote.py`, `database_embedded_kuzu.py` (1311 lines), `database_kuzu.py`, `database_ladybug.py` (a 25-line spec delegating entirely to the Kùzu embedded implementation). `FACT` The backends are not semantically equivalent, and the code says so: a comment at `core/watcher.py:283-287` records that "on Neo4j/Nornic the writer uses CREATE, not MERGE, so duplicate CALLS multiplied on every save. (FalkorDB and Kùzu use MERGE, which is why this never showed up there.)" `FACT` Another divergence at `writer.py:830-836`: a `called.line_number` predicate raises a binder exception on strongly-typed backends but evaluates to null on Neo4j, "which is why dynamic-import edges existed on Neo4j and nowhere else." `FACT` There is a CI job for this class of bug (`.github/workflows/db-parity-check.yml`) and a parity test (`tests/e2e/test_verify_databases_parity.py`).

**Incremental reindex — genuinely diff-driven, and blast-radius aware.** `FACT` `core/watcher.py:255-309`: on a file change it queries the *existing graph* for `get_caller_file_paths()` and `get_inheritance_neighbor_paths()`, forms `affected = {changed} ∪ callers ∪ inheritors`, calls `delete_outgoing_calls_from_files(other_callers)` and `delete_inherits_for_files(other_inheritors)`, re-parses only that subset, and re-runs `link_function_calls` / `link_inheritance` on it. `FACT` `update_file_in_graph` is delete-then-reparse of a single file (`graph_builder.py:993-1022`), and `delete_file_from_graph` DETACH-DELETEs the `File`, its `CONTAINS` children and their `Parameter`s, preserving shared `Module` nodes by deleting only this file's containment edge (`writer.py:1302-1347`). `FACT` Git integration installs managed `post-commit` and `post-checkout` hooks plus a `*.cgc merge=cgc-bundle` merge driver (`cli/hook_manager.py:11-13`). `INFERENCE` This is a stronger incremental story than a content-hash file diff: it recomputes the edges that the change could have invalidated in *other* files, which is the part most incremental indexers skip.

**Bundles.** `FACT` `core/cgc_bundle.py` (1174 lines) serialises an indexed graph into a portable `.cgc` file with a custom encoder (`utils/gcf_encoder.py`); `core/bundle_registry.py:22` pulls prebuilt bundles from a Hugging Face dataset (`codegraphcontext/registry`), exposed as MCP tools `load_bundle` and `search_registry_bundles` (`tool_definitions.py:307`, `:338`).

**Query surface.** `FACT` 30 MCP tools (`src/codegraphcontext/tool_definitions.py`), including `find_code`, `analyze_code_relationships`, `execute_cypher_query`, `find_dead_code`, `calculate_cyclomatic_complexity`, `generate_report`, `find_java_spring_endpoints`, `find_java_spring_beans`, `find_datasource_nodes`, `simulate_metrics`, `simulate_architectural_change`, `analyze_architectural_evolution`.

## 3. Strongest capabilities

- `FACT` **Confidence is a first-class edge property AND a relationship type.** `writer.py:741-746` splits the batch into `precise_batch` / `heuristic_batch` and writes `CALLS` vs `HEURISTIC_CALLS`; `writer.py:856-858` sets `confidence`, `resolution_tier`, `confidence_label` on each. A consumer *can* write `MATCH ()-[r:CALLS]->()` and get only tier ≤ 7.
- `FACT` **Two extraction fidelities behind one schema.** SCIP mode (`scip_indexer.py`, `indexing/scip_pipeline.py`) reuses `GraphWriter` unchanged, so the same MCP tools work over compiler-derived and heuristic graphs. Per-language opt-in via `SCIP_LANGUAGES`.
- `FACT` **Incremental reindex recomputes the affected set from the graph** (callers + inheritors), not just the changed file (`watcher.py:255-309`).
- `FACT` **Real DI and datasource edges.** `INJECTS` for Spring beans; `READS`/`WRITES`/`MAPS_TO`/`HAS_COLUMN`/`STORED_IN` connecting `Function` → `DbTable`/`DbColumn`/`RedisKeyPattern`, sourced from MyBatis mappers and JPA annotations (`tools/languages/mybatis.py`, `tools/languages/java.py`).
- `FACT` **Build-graph nodes**: `MavenModule`, `GradleModule`, `ExternalLibrary` with `MODULE_DEPENDS_ON` / `USES_LIBRARY` / `CHILD_MODULE` from `pom.xml` and Gradle files (`tools/languages/maven.py`, `gradle.py`).
- `FACT` **Backend-parity is treated as a bug class**, with a dedicated CI workflow (`db-parity-check.yml`), an e2e parity test, and source comments naming three specific parity defects (`watcher.py:283-287`, `writer.py:830-836`).
- `FACT` **Golden-file regression harness across 20 languages** — `tests/fixtures/goldens/<lang>/{nodes,edges}.jsonl` compared by `tests/integration/test_parser_goldens.py`, with machine-independent path normalisation via a `/tests/fixtures` marker (`test_parser_goldens.py:29-52`) and volatile-key stripping.
- `FACT` **118 test files**, including `tests/unit/tools/test_calls_resolution_tiers.py`, `test_python_call_resolution_patterns.py`, `test_cross_lang_call_resolution_patterns.py`, `test_module_nodes_and_incremental.py`, `test_cypher_readonly_enforcement.py`, `test_cwe22_path_traversal.py`, `test_imports_map_race.py`.
- `FACT` **Portable graph bundles with a git merge driver** (`cgc_bundle.py`, `hook_manager.py:13`) — the index becomes a committable, mergeable artifact.
- `FACT` **In-repo self-criticism is committed to the tree**: `CGC_GRAPH_INCONSISTENCIES.md` is a 100-item prioritised defect backlog with categories (`resolver`, `structural`, `meta`, `cross_lang`) generated by comparing the indexer to goldens and to a spec.

## 4. Critical weaknesses

- `FACT` **The confidence is never consumed.** `grep -rn "min_confidence\|confidence_threshold\|confidence >" src/` → **no matches**. Every caller/callee/path query in `tools/code_finder.py` (lines 166, 551, 569, 586, 612, 629, 823, 862, 877, 901, 915, 942), `tools/system.py:130`, `report_generator.py` (117, 181, 229, 337, 367) and `java_toolkit.py:239` matches `[:CALLS|HEURISTIC_CALLS]`, including the variable-length traversals `[:CALLS|HEURISTIC_CALLS*1..{max_depth}]`. `INFERENCE` A 5-hop impact query can be built entirely from 0.25- and 0.08-confidence edges and the MCP response will not say so. The data to fix this is already in the graph — the fix is a `WHERE r.confidence >= $t` that nobody wrote.
- `FACT` **Tier 8 is arbitrary-first-candidate name matching, and it is on by default.** `calls.py:1546-1547`: `resolved_path = candidates[0]` where `candidates = imports_map[called_name]`, i.e. every file in the repo that exports that name, in scan order. `INFERENCE` For any repo with a repeated method name (`run`, `execute`, `handle`, `get`), CGC emits a wrong-target edge rather than no edge. There is no ambiguity ceiling, no "decline to resolve" path, and no candidate set retained on the edge for later repair.
- `FACT` **Tier 9 points a call at the caller's own file** (`calls.py:1550`). It only survives if a same-named node exists locally, which is exactly the case where it is most likely wrong (an unrelated local helper shadowing an external method name).
- `FACT` **The interface-dispatch fix and the vector tiebreaker are both default-off** (`ENABLE_INHERIT_RESOLVE`, `ENABLE_VECTOR_RESOLVE` = `"false"`, `config_manager.py:126-127`), as is SCIP. `INFERENCE` The out-of-the-box graph is the least accurate configuration the project ships.
- `FACT` **The accuracy evaluation is circular, by the repo's own admission.** `CGC_CALL_GRAPH_AUDIT_REPORT.md` (dated 2026-06-11) reports "Average FAILURE node accuracy: 99.9% / edge 99.8% / CALLS 98.3%" across 21 languages — but goldens are exports of CGC's own indexer, and `CGC_GRAPH_INCONSISTENCIES.md` item 78 flags "Circular perfection gate (export vs itself) | Indexer vs source truth | Misleading 21/21 PASS", item 79 flags "CALLS avg 84.6% vs perfection 100% | Single metric | Conflicting reports", and item 80 flags a hand-edited golden whose node counts do not match its own `metadata.json` (563/796 vs 482/621). `INFERENCE` **There is no ground-truth accuracy measurement of the graph in this repo.** The goldens catch regressions, not errors — an edge that has always been wrong is "correct" forever.
- `FACT` **Documented schema ≠ implemented schema.** `docs/docs/concepts/graph-model.md` describes `SpringBean` and `SpringEndpoint` node types that do not exist in `src/`; `EXPOSES_ENDPOINT`, `PROVIDES_BEAN` and `FILE_BELONGS_TO` are declared in `schema_contract.py` and written nowhere.
- `FACT` **Six backends with documented behavioural divergence.** Three specific parity defects are recorded in source comments (duplicate `CALLS` on Neo4j from `CREATE` vs `MERGE`; dynamic-import edges existing only on Neo4j; a binder exception silently dropping an entire `Function→File` batch on typed backends — `writer.py:876-879` swallows `_is_binder_exception` with `continue`). `INFERENCE` "Which backend did you index with?" is a required question before trusting any CGC result, and a whole batch of edges can vanish silently.
- `FACT` **No cross-repository edges.** `Repository` is the graph root and every traversal is anchored on `MATCH (r:Repository {path: $path})` (`core/simulator.py:36-39`, `writer.py` deletion paths). Multiple repos can be loaded into one backend, but nothing links a caller in service A to a handler in service B; there is no HTTP/queue/RPC edge type in the 27.
- `FACT` **CSS selectors are stored as `Function` nodes** (`tools/languages/css.py:79-89`), and HTML gets a 139-line extractor. `INFERENCE` These inflate the "23 languages" claim and pollute the `Function` name space that tier-5/8 resolution searches.
- `FACT` **The read-only Cypher guard is a regex keyword blocklist**, not a parser: `_FORBIDDEN_KEYWORDS` (CREATE, MERGE, DELETE, …) plus a handful of APOC/`dbms` patterns, applied after stripping string literals and comments (`utils/cypher_readonly.py:6-40`). `INFERENCE` Blocklist-based sanitisation of a query language is a class of control that is routinely bypassed; it protects the graph, and there is a dedicated test (`test_cypher_readonly_enforcement.py`), but it is not a hard guarantee — especially since the natural-language `ai_query` path (`viz/server.py:548-586`) has an LLM *generate* the Cypher that this regex then vets.
- `FACT` **The HTTP API is unauthenticated by default.** `api/auth.py:7-9`: when `CGC_API_KEY` is unset "every endpoint is unauthenticated" and a warning is logged at startup (`log_auth_status`).

## 6. Security, deployment, and license

- `FACT` **License: MIT** — `.spike/clones/codegraphcontext/LICENSE`, "Copyright (c) 2025-2026" with **no named copyright holder**. `INFERENCE` Standard MIT terms: commercial reuse, vendoring and forking are permitted with attribution. The missing holder name is a paperwork wrinkle, not a restriction — attribution to the project would satisfy it. The bundled VS Code extension carries its own `extensions/vscode/LICENSE`.
- `FACT` Deployment: `pip install codegraphcontext` / `pipx` / `uv tool install`; also a `Dockerfile`, `docker-compose.yml` and a full `k8s/` manifest set (deployment, service, pvc, configmap, `neo4j-secret.example.yaml`). Self-hostable end to end; no SaaS component is required.
- `FACT` Auth/tenancy: single-user local tool by default. The optional FastAPI HTTP surface (`api/app.py`, `api/mcp_sse.py`) is **unauthenticated unless `CGC_API_KEY` is set** (`api/auth.py:7-9`); when set, the key is accepted via `Authorization` or `X-API-Key`, including as a bare token (`auth.py:62-69`). No multi-tenant model, no per-repo ACL.
- `FACT` Network egress in the default path: none for indexing (tree-sitter is local, no LLM in the extraction path). Egress appears in three optional features — the Hugging Face bundle registry (`bundle_registry.py:22,63`), embeddings when `CGC_EMBEDDING_MODEL=openai` (`embeddings.py:15-20`), and the visualiser's natural-language query which calls Gemini, OpenAI, or Atlas Cloud (`viz/server.py:331-386`). `.env.example` documents `ATLASCLOUD_API_KEY` / `ATLASCLOUD_MODEL`.
- `FACT` No telemetry: `grep` finds no analytics/telemetry module in `src/`.
- **Prompt-injection surface.** `FACT` Three distinct paths: (1) `execute_cypher_query` lets the agent run arbitrary Cypher, vetted only by the regex blocklist in `utils/cypher_readonly.py`; (2) `viz/server.py:548-586` has an LLM translate natural language into Cypher which is then run — an untrusted repo docstring surfaced into that prompt can influence the generated query; (3) `load_bundle` / `search_registry_bundles` ingest a **third-party-published graph** from a Hugging Face dataset directly into the local database (`bundle_registry.py`, `tool_definitions.py:307,338`). `INFERENCE` (3) is the sharpest: a poisoned bundle inserts attacker-chosen nodes and edges that the agent then treats as ground truth about the user's code. `UNVERIFIED` whether bundle contents are signed or integrity-checked beyond identifier validation — `tests/unit/core/test_bundle_identifier_validation.py` exists; verifying would require reading `cgc_bundle.py` load path in full.
- `FACT` The repo ships agent-executable artifacts that a reviewer should treat as untrusted: `.cursor/skills/codegraphcontext/SKILL.md` (an agent skill instructing an assistant to install and run `cgc`) and managed git hooks installed by `cli/hook_manager.py`.

## 7. Ideas to adopt or avoid

### Adopt
- **Split the relationship type by confidence, not just a property**: `CALLS` vs `HEURISTIC_CALLS` (`writer.py:741-746`). Specera should do the same — a consumer that writes the obvious query gets the safe answer by default, and opting into low-confidence edges requires typing the scary name. This is strictly better than a confidence column alone, because column-based filtering is opt-*out*.
- **Persist `confidence`, `resolution_tier` and a human label (`EXTRACTED` / `INFERRED` / `AMBIGUOUS`) on every edge** (`calls.py:30-52`, `writer.py:856-858`) — then, unlike CGC, actually filter on it: default every traversal to `confidence >= 0.7`, require an explicit flag to go lower, and surface the tier distribution in every impact answer.
- **One schema, two extraction fidelities.** The SCIP escape hatch (`scip_indexer.py`) is the highest-leverage design in this repo: heuristic tree-sitter for breadth and speed, real compiler indexers (Pyright / tsc / scip-java / scip-clang) for the languages and repos that matter, both writing the same nodes and edges. Specera should design its writer interface so a compiler-grade extractor can be dropped in per language without changing the schema or the query layer.
- **Incremental reindex that queries the graph for the affected set** (`watcher.py:255-269`): `affected = {changed} ∪ callers(changed) ∪ inheritors(changed)`, delete those files' outgoing edges, re-parse, re-link. This closes the stale-inbound-edge hole that a content-hash-only diff leaves open.
- **Semantic framework edges as first-class types**, not metadata JSON: `INJECTS` for DI, `READS`/`WRITES` from `Function` to `DbTable`/`DbColumn`, `MAPS_TO` from endpoint to handler. Specera needs exactly this vocabulary to answer "what touches the `users` table" and "what does the container wire into this controller".
- **A single `schema_contract.py`-equivalent as the one source of truth for labels and edge types, with a test that asserts the writer emits nothing outside it** (`tests/unit/tools/test_schema_contract.py`). Add the reverse assertion CGC lacks: every declared type must be written by at least one code path, which would have caught `EXPOSES_ENDPOINT`, `PROVIDES_BEAN` and `FILE_BELONGS_TO`.
- **A backend-parity CI job** (`.github/workflows/db-parity-check.yml`) if Specera ever supports more than one store. CGC's three documented parity defects — CREATE-vs-MERGE duplicates, null-predicate divergence, and a silently swallowed binder exception dropping a whole edge batch — are the exact bugs this catches.
- **Portable, mergeable index bundles with a git merge driver** (`cgc_bundle.py`, `hook_manager.py:13`, `*.cgc merge=cgc-bundle`). A committed, diffable index that CI can restore is a real answer to cold-start cost on large monorepos.
- **Committing the defect backlog to the repo** (`CGC_GRAPH_INCONSISTENCIES.md`, 100 prioritised items, categorised, each intended to become "one pattern test + one engine fix"). Unusually honest, and it made this analysis faster — which is itself an argument for doing it.

### Avoid
- **Resolving to `candidates[0]` when N candidates match a name** (`calls.py:1546-1547`). Emit nothing, or emit an unresolved-reference record with the full candidate set. A wrong edge is worse than a missing one because it is invisible.
- **Falling back to the caller's own file** for an unresolved `obj.method()` (`calls.py:1550`). This manufactures an edge from the absence of information.
- **Storing quality signals you never read.** CGC computes a 9-tier confidence, labels it, persists it — and then every single query ignores it. Persisting is half the work; the query layer must default to the safe subset.
- **Shipping the least accurate configuration as the default.** SCIP, inheritance re-resolution and the vector tiebreaker are all `false` out of the box (`config_manager.py:112,126,127`).
- **Validating a query language with a regex keyword blocklist** (`utils/cypher_readonly.py`). Parse the query, or run against a read-only credential — do not pattern-match for `CREATE`.
- **Counting CSS and HTML as supported languages** and storing CSS selectors as `Function` nodes (`css.py:79-89`), which contaminates the name space that call resolution searches.
- **Loading third-party prebuilt graph bundles from a public registry into the same store as the user's own index** (`bundle_registry.py`) without signing and provenance labelling on every imported node.
- **Treating self-generated goldens as an accuracy measure.** CGC's own audit says this out loud (item 78). Specera needs at least one hand-labelled ground-truth corpus per language, however small, with published precision *and* recall.

## 8. Build, borrow, buy, integrate, or reject

**Borrow.** MIT (`LICENSE`) makes every mechanism here reusable, and three are worth lifting wholesale: the `CALLS` / `HEURISTIC_CALLS` type split with `confidence` + `resolution_tier` + `confidence_label` on the edge; the SCIP-behind-the-same-writer pattern that lets a compiler-grade extractor replace heuristics per language without touching the schema; and the incremental algorithm that derives the affected file set from the graph (callers ∪ inheritors) rather than from a file hash. Do not integrate CGC as Specera's engine: tier-8 arbitrary-candidate matching is on by default and unfiltered at query time, there are no cross-repository or service-topology edges among the 27 relationship types, the six backends are demonstrably not equivalent, and the repo's own audit establishes that graph accuracy against real ground truth is unmeasured.
